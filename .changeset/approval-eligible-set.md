The approvals block adds `approval_eligible_ids_in(tenants, outside)`, the pending requests the caller may decide in their member tenants (or the tenants passed) from one call, and with `outside => true` the ones outside them, tenantless requests included. Each permission is checked once through `tenant_ids_with` instead of one `can` call per tenant and permission, and a block's `selfDecides` rule runs only for the caller's own requests (the expenses block answers them with one `expense_self_decides_many` call). The function stays `stable` and writes no settings. `approval_eligible_ids(tenant)` calls it and keeps its signature. The approvals page recommends a two-part policy: the member tenants in one call, and the outside set only for rows outside them. With 60 tenants, 2,400 pending requests and a caller who owns 14, three scans in one statement went from 38 ms (filtered to one tenant) and 122 ms (every tenant) with one call per member tenant plus one without a tenant to 6.3 ms and 18 ms. Run `better-supabase upgrade` and generate a migration, then move the policy to the two-part shape. Approvals module version 7, no data step.
