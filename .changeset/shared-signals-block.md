New `shared-signals` block (`better-supabase sql add shared-signals`, `better-supabase/blocks/shared-signals`): an OpenID Shared Signals Framework 1.0 transmitter and receiver, with every CAEP 1.0 and RISC 1.0 event type. `createSsfTransmitter` serves the well-known metadata, stream management, status, verification and RFC 8936 poll routes, and its `authorize` option names the receiver behind each request. `emit` mints one Security Event Token (RFC 8417) per stream that delivers the event, signed by any `signJwt` signer such as a `signing-keys` signer. With `webhooks-out` installed, a push stream (RFC 8935) gets an endpoint with the new `set` format, so SETs go through the outbox with its retries and dead letters. Poll streams queue SETs until they are acknowledged, and a paused stream holds its SETs until it is enabled again. `createSsfReceiver` verifies SETs against the transmitter's JWKS, drops replays through the service-only `ssf_received` table, runs a handler per event type, and serves the push endpoint or polls. Stream changes are recorded as `ssf_stream.*` events. The pins are `SPEC_PINS.rfc8417`, `rfc8935`, `rfc8936`, `ssf`, `caep` and `risc`.
