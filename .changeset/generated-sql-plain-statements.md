The module files `better-supabase gen` writes name `for role postgres` in every `alter default privileges` statement, and the `autoEmbed` drain and the queue `httpTick` job are plain `select cron.schedule(...)` statements, so doctor BS725 no longer reports them under pg-delta. BS725 also accepts a `cron.schedule` call that first checks `pg_cron` is installed (`to_regnamespace('cron')` or `to_regprocedure('cron.…')`). Doctor BS721 no longer reports a platform schema such as `extensions`, a built-in type such as `xid8`, or a call to a function some schema file creates when the call leaves out arguments that have defaults. The declared stages of a pipeline and the declared items of an option set now seed correctly (the `with ordinality` list in the generated function was invalid SQL), and a new migration adds `better_supabase.declared_defaults`. Run `better-supabase gen` and review the module file diff. See the [0.82 to 0.83 guide](https://bettersupabase.com/docs/migration/0.82-to-0.83).
