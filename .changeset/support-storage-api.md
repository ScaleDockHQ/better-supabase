"better-supabase": minor
---

`supportStorage()` and `ctx.storage` return a `StorageApi`, the file API of `supabase.storage`, so `bucket.connect(ctx.storage)` and blocks that take `storage` work in a support session. `list` and `listV2` call `storage.search` and `storage.search_v2` over Postgres as the target, so RLS filters each page as Storage would: a page is no longer shorter than `limit` when some entries are hidden (which ended `bucket.list` and `sweep` early), and the prefix matches without case, as Storage matches it. `exists` and `info` read `storage.objects` as the target, and `download`, `createSignedUrl` and `createSignedUrls` check visibility there before the service client serves the object, now with `transform`, `versionId`, `cacheNonce` and `download` passed through. A hidden object answers like a missing one (`NoSuchKey`), and paths are normalised as storage-js normalises them before the check. `getPublicUrl` is built without a check. Every write resolves to a `403` error with `SUPPORT_READ_ONLY` or `SUPPORT_STORAGE_WRITES`, which a connected bucket maps to `forbidden`. The `SupportStorage`, `SupportStorageAdmin`, `SupportStorageBucket`, `SupportStorageEntry` and `SupportStorageListOptions` types are removed.
