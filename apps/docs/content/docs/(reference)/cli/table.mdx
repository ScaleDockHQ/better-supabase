---
title: table
description: Turn a per-table feature on or off with the @bsb tag in the table comment.
---

```bash
pnpm better-supabase table invoices enable realtime
pnpm better-supabase table public.invoices disable audit
```

`table` edits the `comment on table` statement in the file under `supabase/schemas` that creates
the table (ADR 0102). The free text of the comment stays, and the feature becomes a tag after
`@bsb`. When the file has no comment yet, the command appends one. Run `db diff` afterwards to
write the migration.

| Feature         | Tag             |
| --------------- | --------------- |
| `realtime`      | `realtime`      |
| `audit`         | `audit`         |
| `audit-reads`   | `audit-reads`   |
| `subject`       | `subject`       |
| `json`          | `json`          |
| `expose`        | `expose`        |
| `encrypted`     | `encrypted`     |
| `lookup`        | `lookup`        |
| `server`        | `server`        |
| `events`        | `events`        |
| `vector-search` | `vector-search` |
| `history`       | `history`       |
| `lifecycle`     | `lifecycle`     |

`audit` also appends `select better_supabase.audit('schema.table');` and `expose` appends a
`grant select, insert, update, delete ... to authenticated;` statement, so the migration carries
the trigger or the grant. `disable` removes the statement again. `lookup` takes the encrypted
columns it makes searchable (`@bsb lookup email`). `audit-reads` turns on `auditReads` for the
table's record type. `history title body` keeps the old and new value of those columns through
the `field-history` block, and `lifecycle stage=status pipeline=deals` binds the table to the
`pipelines` block. The last three need a `subject` tag on the table and their block installed.

| Flag        | Effect                                            |
| ----------- | ------------------------------------------------- |
| `--dry-run` | Prints the diff and writes nothing.               |
| `--check`   | Writes nothing and exits 1 when the file differs. |

The command fails when no schema file creates the table, or when two files do.

Side effects: Writes files.
