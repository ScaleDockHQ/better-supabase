---
title: Conformance kits
description: Prove a custom executor, cache adapter, sink, auth resolver, generator or plugin meets its contract.
---

`better-supabase/testing` has a kit per extension interface. A kit runs every
check and resolves with a report, or throws a `ConformanceError` that lists
all failed checks. Kits don't depend on a test runner, so they work in vitest,
`node:test` and bun.

```ts title="kysely-executor.test.ts"
import { testExecutor } from 'better-supabase/testing';
import { it } from 'vitest';

it('conforms', () =>
  testExecutor(kyselyExecutor(db), {
    sb: defineSupabase(schema),
    table: 'tags',
    create: { organizationId: ORG, name: 'conformance' },
  }));
```

| Kit | Checks |
| --- | --- |
| `testExecutor(executor, { sb, table?, create? })` | rows keyed by selection aliases, limits, counts, `aborted` errors, failures returned instead of thrown, rpc failures, and with `create` a create, read and delete round trip |
| `testCacheAdapter(adapter, { table? })` | table and row targets, tenants, repeated and concurrent calls, unknown tables, no mutation of the target |
| `testEventSink(sink, { received? })` | empty and full batches, no mutation of events, and with `received` delivery of every event |
| `testAuthResolver(resolver, { invalid, valid?, unrelated? })` | `undefined` for requests without its credentials, `invalid` (never anon) for bad ones, the expected user for good ones, never throws |
| `testGenerator(generator, { meta, config? })` | relative, unique paths inside the project, deterministic output, no mutation of the input |
| `testPlugin(plugin, { sb, table?, context?, create? })` | API v1, installs and builds every repository, pure and deterministic `transformQuery` and `beforeMutation`, `wrapExecutor` keeps results intact, `mapError` returns a `DbError` or `undefined` |

Inputs that should stay untouched are deep-frozen, so an implementation that
mutates them fails with the check that caught it.

The first-party executors, adapters, generators and plugins run these kits in
the package's own test suite.
