---
title: Conformance blocks
description: Prove a custom executor, cache adapter, sink, auth resolver, framework adapter, generator or plugin meets its contract.
---

`better-supabase/testing` has a block per extension interface. A block runs every
check and resolves with a report, or throws a `ConformanceError` that lists
all failed checks. Blocks don't depend on a test runner, so they work in vitest,
`node:test` and bun.

```ts title="kysely-executor.test.ts"
import { testExecutor } from "better-supabase/testing";
import { it } from "vitest";

it("conforms", () =>
  testExecutor(kyselyExecutor(db), {
    betterSupabase: defineSupabase(schema),
    table: "tags",
    create: { organizationId: ORG, name: "conformance" },
  }));
```

Inputs that should stay untouched are deep-frozen, so an implementation that
mutates them fails with the check that caught it.

The first-party executors, adapters, generators and plugins run these blocks in
the package's own test suite.

## Controller bindings

`testControllerBinding` mounts the binding over a probe controller, the way
a component would. `mount` returns what the component renders (`read`), the
actions it got and an `unmount`; `settle` lets the framework apply pending
updates. The React, Vue, Svelte and Solid bindings of the blocks run it; a
binding for another framework runs it the same way.

```ts title="preact-binding.test.ts"
import { testControllerBinding } from "better-supabase/testing";
import { it } from "vitest";

it("conforms", () =>
  testControllerBinding("preact", {
    mount: (create) => {
      const view = renderHook(() => useController(create));
      return {
        read: () => view.result.current.state,
        actions: view.result.current.actions,
        unmount: view.unmount,
      };
    },
  }));
```
