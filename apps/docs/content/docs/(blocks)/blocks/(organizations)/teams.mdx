---
title: Teams
description: Tenant teams and their members, shared with the inbox.
---

`teams` stores a tenant's teams and who is on them. Creating, changing, archiving, restoring and deleting a team, and changing its members, needs `teams.manage`. `blocks.teams.permissions` can split it: `create` checks `create_team`, `update` checks `update_team`, `archive_team` and `restore_team`, `delete` checks `delete_team`, and `members` checks `add_team_member` and `remove_team_member`. An action you leave unset checks `manage`, so a config without them behaves as before. `team_ids_of(user)` lists the teams a user belongs to. A signed-in caller may only pass their own id (`TEAM_FORBIDDEN` otherwise); the service role and direct database sessions may pass any user's.

```bash
better-supabase add teams
```

```ts
import { createTeams } from "better-supabase/blocks/teams";
```

| Table          | Holds                                                         |
| -------------- | ------------------------------------------------------------- |
| `teams`        | Name, slug, description and status                            |
| `team_members` | A user on a team, with a foreign key to the tenant membership |

`options.teamIdType` is `uuid` (the default) or `bigint`. The inbox needs `uuid`.

`create(organizationId, name, description?, fields?, { slug? })` takes the
slug the app chose (lowercase letters and digits joined by single hyphens;
`TEAM_SLUG_INVALID` otherwise) or derives it from the name.
`update(id, name, description?, fields?, { slug?, description? })` changes
the slug or description it names; `description: null` clears it, which the
plain `description` argument can't. In SQL the change is the `patch jsonb`
argument of `update_team`. `archive(id)` sets a team's status to `archived`
and `restore(id)` back to `active`, recording `team.archived` and
`team.restored`.

## Inbox

The inbox assigns a conversation to a `teams` row. Installing both drops `inbox_teams` and `inbox_team_members` after copying their rows. `create_inbox_team` and `set_inbox_team_member` call the teams functions.

## Over your own tables

Map `tables.teams` and `tables.members` onto the app's tables. CentraKit's team ids are `bigint`, so set `teamIdType` to `bigint` and do not install the inbox module in that project.

## Your own columns

Add columns to the team table with `blocks.teams.options.extraColumns`
(column name to SQL type), then pass a Standard Schema for them as `fields`.
`create` and `update` (the last argument) validates and writes them, and `create`, `update` and `list` return them parsed under
`fields`. A column whose type is `not null` without a `default` is written in
the `insert` itself, so a required column of your own teams table can be set
on create. The block also takes `hooks` around its methods; see
[extending blocks](/docs/extending/blocks).

Server code calls the `teams` instance on `db`, in the caller's organization. With `gen.hooks` set, `better-supabase gen` writes the hooks:

```ts title="src/lib/supabase/hooks.ts"
export const { useList: useTeams } = defineDataHooks(
  "teams",
  (db: AppDb) => db.teams,
);
```

```ts
const rows = await db.teams.list(organizationId).orThrow();
```

```tsx title="src/features/teams/list.tsx"
"use client";

import { useTeams } from "@/lib/supabase/hooks";

const rows = useTeams({ limit: 50 });
```

## Without the client

`db.teams` is this client. Code that does not go through `bsb.db()` builds it with a transport and an organization id:

```ts
import { createTeams } from "better-supabase/blocks/teams";
import { z } from "zod";

const client = createTeams({
  transport,
  fields: z.object({ priority: z.enum(["low", "high"]) }),
});
```
