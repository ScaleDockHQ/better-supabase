---
title: Catalog
description: Products, options and variants, prices in bigint minor units per currency and price list, categories, collections, sales channels, translations, product media and a public storefront switch.
---

`catalog` stores what an organization sells. A product has options (size,
colour), and each variant picks one value per option and carries its own SKU.
Prices live per variant, currency and optional price list, as `bigint` minor
units next to an ISO 4217 code, so an amount never passes through a float.
Categories form a tree, and collections are either a ranked list of products
or a saved filter.

```bash
better-supabase add catalog
```

```ts
import { createCatalog } from "better-supabase/blocks/catalog";
import { money } from "better-supabase/commerce";
```

## Permissions

Every write checks `catalog.manage` in the product's organization, and the
read policies check `catalog.read`. The owner role holds `*`. Give the roles
that work on the catalog these keys:

```ts title="better-supabase.config.ts"
roles: {
  admin: ["catalog.*", "members.*"],
  merchandiser: ["catalog.read", "catalog.manage"],
  member: ["catalog.read"],
},
```

The service role passes every check, for imports and sync jobs.

## Products

Server code calls the `catalog` instance on `db`, in the caller's organization. With `gen.hooks` set, `better-supabase gen` writes the hooks:

```ts title="src/lib/supabase/hooks.ts"
export const { useList: useCatalog } = defineDataHooks(
  "catalog",
  (db: AppDb) => db.catalog,
);
```

```ts
const shirt = await db.catalog
  .createProduct(organizationId, { title: "Linen Shirt", kind: "physical" })
  .orThrow();
// { id, slug: "linen-shirt", status: "draft" }

await db.catalog.setProductStatus(shirt.id, "active").orThrow();
```

```tsx title="src/features/catalog/list.tsx"
"use client";

import { useCatalog } from "@/lib/supabase/hooks";

const rows = useCatalog({ limit: 50 });
```

The slug comes from the title when you leave it out, and it is unique per
organization (`CATALOG_SLUG_TAKEN`). `kind` is `physical`, `digital` or
`service`.

A product starts as `draft`. The built-in transitions are draft to active or
archived, active to draft or archived, and archived back to draft; anything
else fails with `CATALOG_TRANSITION_INVALID`. When a
[state machine](/docs/blocks/state-machine) is declared on the products
table's `status` column, the machine owns the transitions instead, so you can
add a `review` state.

## Options and variants

```ts
const size = await catalog
  .saveOption(shirt.id, { name: "Size", values: ["S", "M", "L"] })
  .orThrow();

await catalog
  .createVariant(shirt.id, {
    sku: "SHIRT-LINEN-S",
    optionValues: [size.values[0].id],
    weightGrams: 220,
  })
  .orThrow();
```

A variant names exactly one value of every option of its product
(`CATALOG_VARIANT_OPTIONS`), and two variants can't pick the same values
(`CATALOG_VARIANT_DUPLICATE`). SKUs are unique per organization
(`CATALOG_SKU_TAKEN`). A product without options has one variant.

Once a product has variants, its options can't gain or lose an option
(`CATALOG_OPTION_HAS_VARIANTS`), and a value a variant uses can't be removed
(`CATALOG_OPTION_VALUE_IN_USE`). Variants keep a rank key, and
`reorderVariant(id, { previous, next })` computes a new one with
[`rankBetween`](/docs/blocks/rank).

`trackInventory` and `allowBackorder` are read by the
[inventory](/docs/blocks/inventory) block when it is installed.

When your variants have no tracking column, map `columns.variants.trackInventory`
to `null` and keep the flag on the product (`columns.products.trackInventory`):
inventory and orders read the product's flag, and `save_variant` refuses a
per-variant one (`CATALOG_TRACK_INVENTORY_UNSUPPORTED`).

### Integer positions

Options, option values, variants, categories and collection products are
ordered by base-62 rank keys. When your rank columns are whole-number
positions, set `options.rankType: "integer"`: a new row goes one after the
last, and `reorderVariant`, `moveCategory` and `addToCollection` take the
position as text (`"3"`).

## Prices

```ts
await catalog
  .setPrice(variantId, {
    amount: money(4900n, "EUR"),
    compareAt: money(5900n, "EUR"),
  })
  .orThrow();

const price = await catalog.variantPrice(variantId, "EUR").orThrow();
// { id, variantId, amount: { amount: 4900n, currency: "EUR" }, compareAt, priceListId: null }
```

Amounts travel as strings and come back as `bigint`, so values beyond
`Number.MAX_SAFE_INTEGER` stay exact. The database checks the currency against
the pinned ISO 4217 list (`CATALOG_CURRENCY_INVALID`) and refuses a
compare-at amount that isn't above the price.

A price can belong to a price list (for a customer group or a market) and can
have a validity window. Two prices for the same variant, currency and list
can't overlap in time (`CATALOG_PRICE_OVERLAP`). `variantPrice` returns the
list price when you pass `priceListId` and one is valid, and the base price
otherwise; `asOf` resolves a price at another instant.

Every change to an amount emits `catalog.price_changed` with the previous
amount, when `outbox` is installed.

### Prices on the variant

When your variants hold their own price, map `tables.prices` to `null`, and
`columns.variants.price` to the variant's price column. A variant without a
price falls back to `columns.products.price`, and the price is in the
product's currency (`columns.products.currency`). `setPrice` writes the
variant's column and refuses another currency, a compare-at amount, a price
list or a validity window; `deletePrice(variantId)` clears the variant's own
price; `variantPrice` returns the variant's or the product's price, and a
price's id is its variant's.

```ts
catalog: {
  tables: { products: "public.products", variants: "public.product_variants", prices: null },
  columns: {
    products: { price: "default_selling_price_cents", currency: "currency", trackInventory: "track_inventory" },
    variants: { price: "selling_price_cents", trackInventory: null, rank: "position" },
  },
  options: { rankType: "integer" },
}
```

## Categories and collections

Categories form a tree per organization. `moveCategory` refuses a move under
its own descendant (`CATALOG_CATEGORY_CYCLE`), and a category with children
can't be deleted (`CATALOG_CATEGORY_HAS_CHILDREN`).
`setProductCategories(productId, ids)` replaces a product's categories.

A manual collection is a ranked list: `addToCollection` appends a product, or
places it between two neighbours. A rule collection stores a filter tree, the
same `FilterQuery` the [list query](/docs/platform/list) reads, so the app
renders it with the filter UI it already has:

```ts
await catalog
  .saveCollection(organizationId, {
    title: "Digital",
    kind: "rule",
    rule: {
      id: "root",
      type: "group",
      combinator: "and",
      rules: [
        {
          id: "kind",
          type: "rule",
          path: ["kind"],
          operator: "is",
          value: "digital",
        },
      ],
    },
  })
  .orThrow();
```

## Channels

A channel is a place the catalog sells through: a web shop, a marketplace or
a point of sale. Each one has a key, a currency and an optional price list,
and lists the products it sells:

```ts
const web = await catalog
  .saveChannel(organizationId, {
    key: "web-de",
    name: "Web shop Germany",
    currency: "EUR",
    priceListId: retailListId,
  })
  .orThrow();

await catalog.listOnChannel(web.id, [shirt.id]).orThrow();

const listed = await catalog
  .channelProducts(web.id, { locale: "de", limit: 50 })
  .orThrow();
// [{ id, slug, status, kind, locale: "de", title, description, listedAt }]

const price = await catalog.channelPrice(web.id, variantId).orThrow();
```

The key is lower-case letters, digits and hyphens, unique per organization
(`CATALOG_CHANNEL_KEY_INVALID`, `CATALOG_CHANNEL_TAKEN`). `listOnChannel` and
`unlistFromChannel` resolve to how many listings they added or removed, and
a product that isn't in the channel's organization fails with
`CATALOG_PRODUCT_NOT_FOUND`. `channelProducts` returns the listed products in
slug order, 100 per page by default and at most 500, with `cursor` for the
next page.

`channelPrice` resolves the variant's price in the channel's currency through
`variantPrice`, so a channel with a price list gets the list price when one is
valid and the base price otherwise. A channel without a currency returns
`null`. Deleting a channel removes its listings, and deleting a price list
clears it on the channels that used it.

## Locales and translations

The `locales` option lists the languages the catalog is written in, as
language tags. The first one is the default, and its text stays on the
product and variant themselves:

```ts title="better-supabase.config.ts"
blocks: { catalog: { options: { locales: ["en", "de", "pt-BR"] } } },
```

```ts
await catalog
  .setProductTranslation(shirt.id, "de", {
    title: "Leinenhemd",
    description: "Aus reinem Leinen.",
  })
  .orThrow();
await catalog.setVariantTranslation(variantId, "de", "Klein").orThrow();

const text = await catalog.productText(shirt.id, { locale: "de-AT" }).orThrow();
// { id, slug, locale: "de", title: "Leinenhemd", description, variants: [{ id, sku, title }] }
```

A read takes any locale and resolves it to a configured one: the locale
itself, then its language (`de-AT` reads `de`), then the default. A field the
translation leaves empty falls back to the default text, so a partial
translation still reads as a whole product. A translation for a locale that
isn't configured fails with `CATALOG_LOCALE_INVALID`, and one for the default
locale fails with `CATALOG_LOCALE_DEFAULT`; update the product instead.
Setting every field to `null` removes the translation. The default is
`["en"]`, and a locale list with a tag twice is refused when the SQL renders.

Options, option values, categories and collections are not translated yet.

## Product media

With [attachments](/docs/blocks/attachments) installed, a product keeps an
ordered list of images and other files, each with alt text per locale and an
optional variant it shows:

```ts
const file = await attachments
  .put(
    { type: "product", id: shirt.id },
    { name: "front.jpg", mimeType: "image/jpeg", size: image.byteLength },
    image,
  )
  .orThrow();

const media = await catalog
  .addProductMedia(shirt.id, file.id, {
    alt: { en: "Linen shirt, front", de: "Leinenhemd, vorne" },
  })
  .orThrow();
// { id, position: 0 }

await catalog.reorderProductMedia(shirt.id, [media.id, otherId]).orThrow();

const gallery = await catalog
  .productMedia(shirt.id, { locale: "de" })
  .orThrow();
// [{ id, attachmentId, variantId, position, alt: "Leinenhemd, vorne", altByLocale }]
```

The attachment must belong to the product or one of its variants
(`CATALOG_MEDIA_ATTACHMENT_NOT_FOUND`), and a file appears in a product's
media once (`CATALOG_MEDIA_TAKEN`). Alt text keys are configured locales
with 1 to 1000 characters (`CATALOG_MEDIA_ALT_INVALID`). `reorderProductMedia`
takes every media item of the product once (`CATALOG_MEDIA_ORDER_INVALID`),
and `removeProductMedia` closes the gap it leaves. Deleting the attachment
removes its media item. `updateProductMedia` changes the variant and the alt
text.

## Storefront

Set the `storefront` option to `public` to let anyone read the published
catalog of an organization:

```ts title="better-supabase.config.ts"
blocks: { catalog: { options: { storefront: "public" } } },
```

With it, `anon` can read the active products of organizations that called
`publishStorefront(organizationId, true)`, their variants, options,
categories and collections, and their base prices (prices without a price
list). Price lists stay private. The default, `private`, adds no `anon`
policies.

The storefront also reads active channels and their listings, translations
and product media. `channelProducts`, `channelPrice`, `productText` and
`productMedia` are granted to `anon`, and they return only what these
policies allow. A media row names its attachment; the file itself stays
behind the attachments block's own policies.

## Subjects

Installing the block registers products (`product`) and variants
(`product_variant`) as subjects, so comments, tags, attachments and search
work on them. A product links to `/products/{slug}` unless you set its page:

```ts title="better-supabase.config.ts"
blocks: {
  catalog: { entities: { product: { url: "/admin/products/{id}" } } },
},
```

## Events

| Event                                                   | When                                      |
| ------------------------------------------------------- | ----------------------------------------- |
| `product.created`, `product.updated`                    | `createProduct`, `updateProduct`          |
| `product.status_changed`                                | A status transition, with `from` and `to` |
| `product.deleted`                                       | `deleteProduct`                           |
| `variant.created`, `variant.updated`, `variant.deleted` | A variant change                          |
| `catalog.price_changed`                                 | A price's amount changes                  |
| `storefront.published`, `storefront.unpublished`        | `publishStorefront`                       |

## Hooks

The SQL module calls `before_product_save`, `after_product_save`,
`before_variant_save`, `after_variant_save`, `before_price_set` and
`after_price_set` when you define them (see [blocks](/docs/extending/blocks)).
The TypeScript client takes `hooks` keyed by method name.

## Adopting existing tables

To run over tables you already have, map `products`, `variants` and `prices`
to yours. Every other table is optional: set it to `null` and the functions that need it are
left out. Columns such as `description`, `barcode`, `compareAt` or
`validFrom` can also be `null`.

The tables added in version 3 (`channels`, `channelProducts`,
`productTranslations`, `variantTranslations` and `media`) run over a table of
yours only when `tables` maps them. Unmapped, the module creates its own, so
a table of yours under one of those default names is an error until you map
it.

## Not included

Product import from CSV goes through the [imports](/docs/blocks/imports)
block with a mapping you write. Rule collections are not evaluated in SQL;
the app runs the stored filter through its list query. Price lists don't
know who belongs to a customer group yet, so only base prices are public.

## Your own fields

`blocks.catalog.options.extraColumns` adds columns to the `products` table,
keyed by column name with their SQL type. Pass `createCatalog` a Standard Schema
for them as `fields`: `createProduct`, `updateProduct` take them next to the block's own keys and
validate them (a bad value is a `validation` error), and the saved product return them
parsed. A column the module already uses is refused. See
[your own fields](/docs/extending/blocks#your-own-fields).

```ts
const client = createCatalog({
  transport,
  fields: z.object({ priority: z.number().int().positive().nullable() }),
});
```

## Without the client

`db.catalog` is this client. Code that does not go through `bsb.db()` builds it with a transport and an organization id:

```ts
const catalog = createCatalog({ transport });

const shirt = await catalog
  .createProduct(organizationId, { title: "Linen Shirt", kind: "physical" })
  .orThrow();
// { id, slug: "linen-shirt", status: "draft" }

await catalog.setProductStatus(shirt.id, "active").orThrow();
```
