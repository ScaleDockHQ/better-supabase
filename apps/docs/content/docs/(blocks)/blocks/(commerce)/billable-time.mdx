---
title: Billable time
description: Price tracked time with an hourly rate card per organization, member and record, preview what it would bill, and turn it into draft invoice lines in bigint minor units.
---

`billable-time` connects [time tracking](/docs/blocks/time-tracking) to
[invoices](/docs/blocks/invoices). You keep a rate card of hourly rates, see
what the unbilled time on a project or customer would bill, and put it on a
draft invoice in one call. Each billed entry remembers the invoice and the
rate it was billed at, so it can't be billed twice.

```bash
better-supabase add billable-time
```

```ts
import { createBillableTime } from "better-supabase/blocks/billable-time";
import { money } from "better-supabase/commerce";
```

The module requires `tenant`, `access`, `subjects`, `time-tracking` and
`invoices`. With `outbox` it records a `time_entry.invoiced` event, and with
`audit` rate changes and invoicing are audited. Amounts are bigint minor
units ([ADR 0037](https://github.com/ScaleDockHQ/better-supabase/blob/main/docs/decisions/0037-money-on-the-wire.md)),
and the choices behind locking billed time are in
[ADR 0074](https://github.com/ScaleDockHQ/better-supabase/blob/main/docs/decisions/0074-billable-time-rate-card.md).

It reads entries the way time tracking stores them. When the entries table
keeps a column per record type (`blocks.time-tracking.on.<type>.column`), an
entry's record comes from that column; when it keeps a start and a duration
(`endedAt` mapped to `null`), an entry ends at its start plus `seconds` and a
running timer is never billed.

## Tables

| Table                  | Holds                                                                                                                                                                                   |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `time_rates`           | The rate card: an hourly `rate`, an optional hourly `cost_amount` and `currency`, an optional member (`user_id`) and record (`subject_type`, `subject_id`), and the day it takes effect |
| `time_invoice_entries` | One row per billed time entry: the invoice, the rate and currency it was billed at, and the seconds billed                                                                              |

Both tables are read through the functions only. Members with
`billable_time.read` read the rate card and the billed entries.

## Set rates

Server code calls the `billable-time` instance on `db`, in the caller's organization. With `gen.hooks` set, `better-supabase gen` writes the hooks:

```ts title="src/lib/supabase/hooks.ts"
export const { useList: useBillableTime } = defineDataHooks(
  "billableTime",
  (db: AppDb) => db.billableTime,
);
```

```ts
await db.billableTime.setRate({ rate: money(9000n, "EUR") }).orThrow();
await db.billableTime
  .setRate({ rate: money(12000n, "EUR"), subject: { type: "projects", id } })
  .orThrow();
await db.billableTime
  .setRate({
    rate: money(15000n, "EUR"),
    userId,
    subject: { type: "projects", id },
  })
  .orThrow();
```

```tsx title="src/features/billable-time/list.tsx"
"use client";

import { useBillableTime } from "@/lib/supabase/hooks";

const rows = useBillableTime({ limit: 50 });
```

A rate without `userId` and `subject` is the organization's rate. A rate can
name a member, a record in `config.subjects`, or both. For each entry the most
specific rate wins: the member on the record, then the record, then the
member, then the organization. A rate takes effect on `effectiveFrom`
(default today) and stays until a newer rate on the same key takes over, so a
raise doesn't change what older time bills. The day is read in the
time-tracking block's `timeZone`. Setting a rate on the same key and day
replaces it. An entry that carries its own `rate` keeps that rate. Setting
and deleting rates needs `billable_time.manage`.

A rate can also carry a `cost`, what an hour costs you, in the rate's
currency. Project costing values time at the cost of the rate that applies.

| Method                             | Returns                                                    |
| ---------------------------------- | ---------------------------------------------------------- |
| `setRate(input)`                   | the rate                                                   |
| `deleteRate(rateId)`               | the deleted rate                                           |
| `listRates({ userId, subject })`   | the rate card                                              |
| `rateFor({ userId, subject, on })` | the rate that applies, or `null`                           |
| `unbilled(query)`                  | the lines, one total per currency, and the unrated entries |
| `invoice(input)`                   | the draft invoice's id, its total and the billed entry ids |
| `invoicedEntries(invoiceId)`       | the entries an invoice billed, with their rates            |
| `projectCosts(projectId)`          | a project's costs, revenue, margin and budget use          |

## Preview and invoice

```ts
const preview = await billing
  .unbilled({ subject: { type: "projects", id } })
  .orThrow();

const { invoiceId, total } = await billing
  .invoice({
    subject: { type: "projects", id },
    company: { type: "companies", id: companyId },
    title: "October",
    termsDays: 30,
  })
  .orThrow();
```

`unbilled` shows what `invoice` would bill without billing it. Only finished
entries marked billable that aren't on an invoice count. A line's `quantity`
is hours to four decimals, as text; its `amount` is the quantity times the
hourly rate, rounded to a minor unit. `unrated` lists the entries no rate
covers.

`invoice` creates a draft with the [invoices](/docs/blocks/invoices) block
and adds a line per group, all in one transaction. It fails with
`TIME_RATE_MISSING` while an entry has no rate, and with
`BILLABLE_TIME_CURRENCIES` when the entries bill in more than one currency
and `currency` doesn't pick one. The title defaults to `Time`. Invoicing
needs `billable_time.invoice` and `invoices.write`.

The scope narrows the entries: `subject`, `userId`, `starts` and `ends` (by
start time), and `entryIds`. `groupBy` decides the lines:

| `groupBy`           | One line per                 |
| ------------------- | ---------------------------- |
| `subject` (default) | record and rate              |
| `member`            | record, member and rate      |
| `entry`             | entry, described by its note |

## Billed time is locked

A billed entry can't be deleted, and its start, end (or duration and running
mark), billable flag and rate can't change: the database raises
`TIME_ENTRY_INVOICED`. Its record can still
change, so merging two records keeps working. Voiding the invoice releases
its entries, and they show up in `unbilled` again.

An organization purge deletes the billed rows with the invoices. Erasing a
member doesn't delete their billed time; it stays as an accounting record
until the invoice is voided.

## Project costing

With the [tasks](/docs/blocks/tasks) block and its projects table installed,
`projectCosts(projectId)` adds up what a project cost and earned. It needs
`billable_time.read`.

```ts
const costs = await db.billableTime.projectCosts(projectId).orThrow();

costs.totals; // [{ currency, timeCost, billed, expenses, income, margin }]
costs.budgetUsed; // { hours: 0.5, amount: 0.68 }
```

It counts the finished time on the project (when your app registers
projects as a record type) and on the project's work items. `timeCost` is
that time at the rate card's `cost`, and `uncostedHours` the time no cost
covers. `billed` is the time billed on invoices at the billed rate. With
[accounting](/docs/blocks/accounting) installed, `expenses` and `income` are
the posted expense and income lines whose `project` dimension is the project,
such as expense claims and purchase bills booked to it. Leave the `project`
dimension off invoice lines that bill time, or that revenue counts twice. The
margin is `billed` and `income` less `timeCost` and `expenses`, per currency.
`budgetUsed` compares the hours to the project's `budgetHours`, and the time
cost and expenses in the budget's currency to its `budget`.

## Errors

| Hint                             | Cause                                                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `BILLABLE_TIME_FORBIDDEN`        | the caller lacks `billable_time.read`, `.manage` or `.invoice`                                                     |
| `TIME_RATE_INVALID`              | the rate or cost is negative, the currency isn't a currency code, or only one of the record type and id was passed |
| `TIME_RATE_COST_UNSUPPORTED`     | the rate table has no cost column                                                                                  |
| `TIME_RATE_SUBJECT_INVALID`      | the record is unknown or not in the organization                                                                   |
| `TIME_RATE_MEMBER_INVALID`       | `userId` isn't a member of the organization                                                                        |
| `TIME_RATE_NOT_FOUND`            | no rate with this id in the organization                                                                           |
| `BILLABLE_TIME_GROUPING_INVALID` | `groupBy` isn't `subject`, `member` or `entry`                                                                     |
| `TIME_RATE_MISSING`              | a billable entry has no rate                                                                                       |
| `BILLABLE_TIME_CURRENCIES`       | the entries bill in more than one currency and none was picked                                                     |
| `BILLABLE_TIME_EMPTY`            | the scope selects no unbilled time                                                                                 |
| `INVOICE_NOT_FOUND`              | `invoicedEntries` named an invoice outside the organization                                                        |
| `TIME_ENTRY_INVOICED`            | the entry is on an invoice; void the invoice to change it                                                          |
| `TASK_PROJECT_NOT_FOUND`         | `projectCosts` named a project the caller can't read                                                               |

## Events

`time_entry.invoiced` when time is billed. The
[events page](/docs/extending/events) lists its payload.

## Without the client

`db.billableTime` is this client. Code that does not go through `bsb.db()` builds it with a transport and an organization id:

```ts
const billing = createBillableTime({ transport, tenant: organizationId });

await billing.setRate({ rate: money(9000n, "EUR") }).orThrow();
await billing
  .setRate({ rate: money(12000n, "EUR"), subject: { type: "projects", id } })
  .orThrow();
await billing
  .setRate({
    rate: money(15000n, "EUR"),
    userId,
    subject: { type: "projects", id },
  })
  .orThrow();
```

## Work in progress

`wipValuation(asOf)` values the unbilled time on a day (today by default): the
finished, billable entries no invoice has billed, at the rate card's cost and
at its billing rate, per currency. It needs `billable_time.read`.

```ts
const wip = await db.billableTime.wipValuation().orThrow();

wip.totals; // [{ currency, cost, billable }]
wip.uncostedHours; // time the rate card has no cost for
```

Materials are not part of it: stock movements are costed on the ledger.
