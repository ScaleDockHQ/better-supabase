Installs the blocks behind a care provider as one: the client record and its team, clinical blocks, scheduling, staffing, training and controlled documents. It sets the care defaults.

```bash
better-supabase add care
```

```ts title="better-supabase.config.ts"
export default defineConfig({ blocks: { care: {} } });
```

`add` lists `care` in `blocks`, writes the modules of every part and wires the client in `lib/blocks.ts`. Import the manifest from `better-supabase/blocks/care` when you build the set with [`createBlocks`](/docs/blocks/create-blocks).

```ts
import { careBlock } from "better-supabase/blocks/care";
```

## Defaults

It sets person records to audit reads with a record team, vital signs as the observation defaults, an incident case kind for missed doses, and the case kinds incident, employee incident and complaint. It also controls protocol, policy, procedure, work instruction and form document types in the drive.

The app's own `blocks.<part>` settings win key by key ([Composite blocks](/docs/extending/composite-blocks)).

## Remove

```bash
better-supabase remove care
better-supabase remove care --with-parts
```

The first command replaces `care` in `blocks` with its parts. The second removes the parts too, except any part another block still needs ([`remove`](/docs/cli/init#remove)).
