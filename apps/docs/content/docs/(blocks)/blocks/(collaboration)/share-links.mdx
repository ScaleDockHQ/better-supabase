---
title: Share links
description: Hashed share links, view counts and per-user state. The token is returned once.
---

`share-links` creates a link, returns the token once and stores only its SHA-256. `resolve_share_link` is granted to `anon` and hashes the token it is given, so a row that still holds a plaintext token keeps working after you store `sha256` of it. Revoking, listing, recording a view and setting starred or last-opened state are the other calls.

```bash
better-supabase add share-links
```

```ts
import { createShareLinks } from "better-supabase/blocks/share-links";
```

When the rate-limit module is installed, resolve is a place to apply it.

`create(subject, { role, versionId, expiresAt })` takes the subject as a `RecordRef` (`{ type, id }`) and acts in the block's `tenant`. It takes the role (`view` by default), an optional `Temporal.Instant` after which the link stops resolving and, with the [versions](/docs/blocks/versions#share-a-version) module installed, a version of the subject to pin the link to. An `expiresAt` that is not in the future fails with `SHARE_EXPIRY_INVALID`. `resolve(token)` returns the link's id, `organizationId`, `subject` (a `RecordRef`), role, `versionId` and `expiresAt`, or `null` when the token is unknown, revoked or expired.

```ts
const link = await shareLinks
  .create(
    { type: "calendar", id: calendarId },
    { expiresAt: Temporal.Now.instant().add({ hours: 24 * 30 }) },
  )
  .orThrow();
```

The other calls on a subject take it the same way: `list(subject)` returns its
links, `recordView(subject, viewerKind, viewer?)` counts a view in the
block's tenant, and `setState(subject, starred)` stars or unstars it for the
caller. A call that needs a tenant and has none fails with `invalid_request`
and the hint `TENANT_REQUIRED`.

## Permissions

| Call         | Who may call it                                                                                          |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| `create`     | a member with `share_links.create` in the organization                                                   |
| `revoke`     | the link's creator, or a member with `share_links.create`; anyone else gets `SHARE_NOT_FOUND`            |
| `list`       | the links the caller created, plus every link in organizations where the caller holds `share_links.read` |
| `recordView` | a member of the organization (`SHARE_FORBIDDEN` otherwise)                                               |
| `resolve`    | anyone, including `anon`                                                                                 |

The service role may make every call.

### Sharing one record

A record type that declares a `share` action in
[`config.records`](/docs/blocks/sql#actions-granted-per-row) is checked per
record as well: `create` needs that action on the record, and `revoke` and
`list` need it on top of the organization key, so only the creator or someone
who may share the record sees and revokes its links. The action can be a key,
a per-row grant from the authorization provider or an owner column:

```ts title="better-supabase.config.ts"
export default defineConfig({
  records: {
    file: {
      table: "public.files",
      idType: "uuid",
      permissions: { share: { key: "file.update", rows: "file" } },
    },
    thread: {
      table: "public.threads",
      idType: "uuid",
      permissions: { share: { owner: "owner_id" } },
    },
  },
});
```

Without a `share` action, the record only has to exist in the link's
organization, as before.

### Tokens you make and full rows

Two options fit an app that already has links:

| Option            | What it adds                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tokenHash: true` | `create_share_link(..., token_hash)` stores the SHA-256 hex of a token the app made (64 lowercase hex characters, `SHARE_TOKEN_HASH_INVALID` otherwise) and returns no token; `find_share_link(token_hash)` returns the live link a hash names without counting a use, for the service role. The client calls them as `createHashed(subject, tokenHash, options)` and `find(tokenHash)` |
| `fullRows: true`  | `list_share_links` returns each link's `organizationId`, `subjectType`, `subjectId`, `createdBy` and `createdAt` (a `createdAt` column the block adds to its own table), newest first, and takes `include_revoked` (the client's `list(subject, { includeRevoked: false })`)                                                                                                            |

Without them the functions keep the signatures of earlier releases.

## Events

| Event                | When                        |
| -------------------- | --------------------------- |
| `share_link.created` | `create` stored a link      |
| `share_link.revoked` | `revoke` revoked one        |
| `subject.viewed`     | `recordView` counted a view |

## Guest pages

Every module that reads a subject through a link (calendar feeds, booking pages, public forms, drive links, shared AI chats, shared versions) checks the same four things: the token's hash, the subject type, that the link is not revoked and that it has not expired. A guest page has two ways to read the subject:

- Call the module's own function (`calendar_feed(token)`, `get_public_form(token)`, `get_shared_version(token)`). It is `security definer`, returns only what the link grants and needs no session.
- Exchange the token for a short-lived anonymous session whose claims name the link, then query under row-level security. An authorization provider can do this from the row `resolve` returns; see [Authorization providers](/docs/extending/authorization-providers#share-links-as-guests). Keep the token's lifetime capped by the row's `expiresAt`, and revoke the row to end every session minted from it.

## AI chat

AI chat sharing uses this block. `share_ai_chat`, `revoke_ai_chat_share`, `list_ai_chat_shares` and `get_shared_ai_chat` stay callable and read or write `share_links`. Existing `ai_chat_shares` rows are copied, including `leaf_id`.

## Over your own tables

To run over tables you already have, map `tables.links`, `tables.views` and `tables.state`. The block stores a SHA-256 hash of each token, so a table that keeps plaintext tokens needs `update ... set token = encode(sha256(convert_to(token, 'utf8')), 'hex')` once. Your own view and per-user state tables map onto `views` and `state` when their columns fit. `views` and `state` are optional: map either to `null`, over your tables or the block's own, and the block creates no such table, `record_view` counts no views and `set_user_state` keeps no state.

## Your own columns

Add columns to the share link table with `blocks.share-links.options.extraColumns`
(column name to SQL type), then pass a Standard Schema for them as `fields`.
`create` (in its options) validates and writes them, and `create` and `list` return them parsed under
`fields`. The block also takes `hooks` around its methods; see
[extending blocks](/docs/extending/blocks).

Server code calls the `share-links` instance on `db`, in the caller's organization. With `gen.hooks` set, `better-supabase gen` writes the hooks:

```ts title="src/lib/supabase/hooks.ts"
export const { useList: useShareLinks } = defineDataHooks(
  "shareLinks",
  (db: AppDb) => db.shareLinks,
);
```

```ts
const rows = await db.shareLinks.list({ limit: 50 }).orThrow();
```

```tsx title="src/features/share-links/list.tsx"
"use client";

import { useShareLinks } from "@/lib/supabase/hooks";

const rows = useShareLinks({ limit: 50 });
```

## Without the client

`db.shareLinks` is this client. Code that does not go through `bsb.db()` builds it with a transport and an organization id:

```ts
import { createShareLinks } from "better-supabase/blocks/share-links";
import { z } from "zod";

const client = createShareLinks({
  transport,
  fields: z.object({ priority: z.enum(["low", "high"]) }),
});
```
