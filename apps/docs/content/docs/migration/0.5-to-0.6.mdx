---
title: From 0.5 to 0.6
description: What to change when upgrading to better-supabase 0.6, which renames kits to blocks, moves the feature modules under better-supabase/blocks and spells out organization.
---

0.6 renames kits to blocks and moves every feature module under
`better-supabase/blocks/<name>`. Names that said `org` now say `organization`,
in TypeScript, in SQL and in event types. This release is a clean break: the
old names have no aliases or SQL wrappers, so update imports, config and SQL in
one change.

## Update imports

| 0.5                                                                        | 0.6                                                               |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `createOrgs` from `better-supabase/orgs`                                   | `createOrganizations` from `better-supabase/blocks/organizations` |
| `better-supabase/jobs` (queue, cron, idempotency, inbox)                   | `better-supabase/blocks/jobs`                                     |
| `createOutbox`, `outboxCloudEvent` from `better-supabase/jobs`             | `better-supabase/blocks/outbox`                                   |
| `entitlementMembers`, `ENTITLEMENTS_UPDATED` from `jobs`                   | `better-supabase/blocks/entitlements`                             |
| `hasEntitlement`, `EntitlementKey` from `server`, `next`, `ssr` or `react` | `better-supabase/blocks/entitlements`                             |
| `better-supabase/notifications`                                            | `better-supabase/blocks/notifications`                            |
| `useNotifications` from `better-supabase/react`                            | `better-supabase/blocks/notifications/react`                      |
| `better-supabase/webhooks`                                                 | `better-supabase/blocks/webhooks`                                 |
| `orgLogoBucket`                                                            | `organizationLogoBucket`                                          |

Types follow the same pattern: `Orgs`, `OrgsOptions`, `CreateOrgOptions`,
`OrgAttributes` and `OrgEventData` become `Organizations`,
`OrganizationsOptions`, `CreateOrganizationOptions`, `OrganizationAttributes`
and `OrganizationEventData`. Every `Kit` name becomes `Block`: `KitsConfig` is
`BlocksConfig`, `KitEvent` is `BlockEvent`, `onKitEvent` is `onBlockEvent`,
`forwardKitEvents` is `forwardBlockEvents`, `KIT_ATTRIBUTES` is
`BLOCK_ATTRIBUTES` and `renderKit` is `renderBlocks`.

`list`, `storage`, `realtime` and `events` keep their subpaths.

## Update the config

The `kits` key becomes `blocks`, and `sql.kit` (the modules to keep in sync)
becomes `sql.modules`:

```ts title="better-supabase.config.ts"
export default defineConfig({
  blocks: { access: { roles: ["owner", "admin", "member"] } },
  sql: { modules: ["access", "organizations", "invitations"] },
});
```

## Update event types

The organization events are now `organization.created`,
`organization.updated`, `organization.deleted`, `organization.role_changed`,
`organization.member_added`, `organization.member_removed`,
`organization.member_left`, `organization.ownership_transferred` and
`organization.switched`. Update `sb.on` patterns, outbox consumers and
webhook subscriptions that name an `org.*` type.

## Regenerate the SQL modules

The module files now start with `-- @bs-block`, and the module registry table
is `better_supabase.block_modules`. These SQL functions were renamed:

| 0.5                                            | 0.6                                              |
| ---------------------------------------------- | ------------------------------------------------ |
| `member_org_ids(roles)`                        | `member_organization_ids(roles)`                 |
| `has_org_role(org, roles)`                     | `has_organization_role(organization, roles)`     |
| `org_member_role(org, member)`                 | `organization_member_role(organization, member)` |
| `org` parameters of the organization functions | `organization`                                   |

Update your policies and RPCs that call them, then rewrite the module files and
create the migrations:

```bash
better-supabase sql sync
supabase db schema declarative sync
better-supabase sql data
```

The schema diff drops `kit_modules` and the old functions and creates the new
ones, and `sql data` writes the `block_modules` rows into a migration after it.
A function whose parameter was renamed can't be replaced in place, so apply
the files through the diff rather than by running them on the database.
