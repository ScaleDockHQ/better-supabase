---
title: Errors
description: What each CLI error code means, its exit code, and how to fix it.
---

Every error the CLI reports has a code. In a terminal it prints the message
on stderr. With `--json` the [result envelope](/docs/cli#exit-codes-and-json-output)
on stdout holds a [Problem Details](https://www.rfc-editor.org/rfc/rfc9457)
document under `error`, whose `type` links to the code's section on this
page:

```json
{
  "$schema": "https://unpkg.com/better-supabase/schemas/cli-result-v1.json",
  "status": "error",
  "error": {
    "type": "https://bettersupabase.com/docs/cli/errors#unknown_command",
    "title": "Unknown command",
    "detail": "Unknown command \"genn\". Did you mean \"gen\"?",
    "code": "unknown_command",
    "exitCode": 2,
    "suggestion": "gen"
  }
}
```

The exit code tells a script what to do next:

| Exit code | Meaning                                                                                     |
| --------- | ------------------------------------------------------------------------------------------- |
| 0         | The command succeeded.                                                                      |
| 1         | The command ran and failed, or found something (`--check` drift, doctor errors).            |
| 2         | The command line, the config or the environment needs a change; a rerun fails the same way. |
| 3         | The user has to act first: give an input, consent to a change, or log in.                   |
| 65        | `gen --metadata` rejected its GeneratorMetadata document.                                   |
| 130       | The run was interrupted (Ctrl-C) or a prompt was cancelled.                                 |
| 143       | The process received SIGTERM.                                                               |

## `usage`

An option is missing, unknown or has the wrong value. The message names the
option, and the text output adds the command's usage. Exit code 2.

## `unknown_command`

The first argument isn't a command. When one is close enough to be a typo,
`suggestion` names it. Run `better-supabase --help` for the list. Exit
code 2.

## `command_moved`

The command or flag was renamed. `suggestion` holds the new form, which you
can run as is. Exit code 2.

## `missing_value`

The command needs a value it didn't get, such as `SUPABASE_ACCESS_TOKEN` for
`--project-ref`, a connection string on stdin for `--db-url-stdin`, or a
directory for `--cwd`. A stdin flag reports it at once when stdin is a
terminal instead of waiting for input. `flag` names the variable or option
that supplies it. Exit code 2.

## `outside_root`

A path option points outside the project root, for example
`--out ../.env.local`. Run the command from the project that owns the file.
`flag` names the option. Exit code 2.

## `config_not_found`

`--config` points at a file that doesn't exist. The path is relative to
`--cwd`. Exit code 2.

## `config_invalid`

`better-supabase.config.*` failed to load, or has a key or value the CLI
doesn't accept. `issues` lists each problem as `path: message`, for example
`codecs.timestamptz: Invalid type`. Exit code 2.

## `env_invalid`

An environment variable the CLI reads has a malformed value, for example a
`DATABASE_URL` that isn't a URL. `issues` lists each variable. Exit code 2.

## `not_found`

A file or module the command reads doesn't exist, such as a snapshot or an
entry named in the config. Exit code 1.

## `invalid_input`

A file the command reads exists but holds the wrong thing: a snapshot of an
older version, a status file without `supabase status` JSON, or an entry
that exports no topic or read set. Exit code 1.

## `dependency_missing`

The command needs an optional package the project hasn't installed, such as
`pg` to read a database. `suggestion` holds the install command. Exit
code 1.

## `database_unreachable`

The CLI couldn't connect to the database. The message has the redacted URL
and the driver's error. For a local URL that refused the connection,
`suggestion` is `supabase start`. Exit code 1.

## `supabase_cli_missing`

The command runs the Supabase CLI and found none: not `$SUPABASE_BIN`, not
`node_modules/.bin/supabase`, and not `supabase` on the `PATH`. The CLI never
downloads one. Install it with `pnpm add -D supabase`. Exit code 1.

## `supabase_cli_failed`

The Supabase CLI ran and failed, or printed output the command can't read.
Check that the local stack runs (`supabase start`). Exit code 1.

## `request_failed`

An HTTP request failed, such as a Management API query or the download of
the pinned `splinter.sql`. The message has the status and the start of the
response. Exit code 1.

## `auth_required`

A request was refused with 401 or 403. Check that `SUPABASE_ACCESS_TOKEN` is
set and can read the project. Exit code 3.

## `integrity_failed`

A downloaded file didn't match its pinned hash, so the CLI refused to run
it. Exit code 1.

## `generator_failed`

A generator threw, or wrote a file outside the project root or a file that
another generator writes. The message names the generator. Exit code 1.

## `check_failed`

`--check` found files that are out of date. Run the command without
`--check` to write them. Exit code 1.

## `file_conflict`

A file the command generates already exists without the better-supabase
header, so the app wrote it by hand. The command leaves it alone and lists it
as Skipped. Move your code elsewhere, or pass `--force` to overwrite it. Exit
code 1.

## `findings`

A check such as `doctor` or `spec validate` found problems at or above the
`--fail-on` level. The report lists them. Exit code 1.

## `input_required`

The command needs an answer it would prompt for, and it can't prompt (in CI,
under `--json` or for an agent). `next` holds the command to run with the
answer filled in. Exit code 3.

## `consent_required`

The command would make a destructive change, and needs the user's explicit
consent. Rerun it with the `--confirm <token>` that `next` shows; `--yes`
doesn't replace it. Exit code 3.

## `cancelled`

The person cancelled a prompt with Ctrl-C or Escape. Nothing after the
prompt ran. Exit code 130.

## `failed`

The command ran and reported a failure. `exitCode` is the command's own exit
code, usually 1.

## `internal`

Something the CLI didn't expect went wrong. `detail` has the underlying
message. Exit code 1. If it looks like a bug,
[open an issue](https://github.com/ScaleDockHQ/better-supabase/issues) with
the command and the message.
