---
title: Audit log
description: List, filter and export a tenant's audit entries as NDJSON or OCSF, and purge them per tenant's retention.
---

The `audit` SQL module records row changes and `audit_event()` calls (see
[SQL modules](/docs/blocks/sql#audit-log)). The audit block reads that log
from TypeScript: a list for an activity page, an export for customers and
SIEMs, and retention.

```bash
better-supabase sql add audit
```

Turn on `readPolicy` so members read their tenant's entries with
`audit.read`, and platform staff read every entry:

```ts title="better-supabase.config.ts"
export default defineConfig({
  sql: { modules: { audit: { options: { readPolicy: true } } } },
});
```

## Listing entries

`auditListQuery` is a [list query](/docs/platform/list) over the
audit table, newest first behind a cursor, with facets for `table`, `record`,
`op`, `actor`, `event`, `category`, `outcome` and `target` (those the table
has). Generate types for the `better_supabase` schema so the table is in your
models, then:

```ts title="app/settings/audit/list.ts"
import { auditListQuery } from "better-supabase/blocks/audit";

export const auditList = auditListQuery(betterSupabase, "auditEvents");

const query = auditList.parse(searchParams);
if (!query.ok) return badRequest(query.issues);
const page = await auditList
  .run(ctx.db, query.value, {
    where: { organizationId, ...auditList.between(from, to) },
  })
  .orThrow();
```

`between(from, to)` filters `occurred_at` to `[from, to)`. The read policy
decides which rows a member sees; restricted columns stay in the
`audit_events_restricted` table, which members can't read.

## Exporting

`exportAuditLog` streams one tenant's entries as newline-delimited JSON, one
keyset query per batch, so memory stays flat however long the log is. Run it
with a member's claims, so the read policy applies, or as the service role:

```ts title="app/api/audit/export/route.ts"
import { exportAuditLog } from "better-supabase/blocks/audit";

export const GET = bs.handler(async (request, ctx) => {
  if (ctx.auth.kind !== "user") return new Response(null, { status: 401 });
  const stream = exportAuditLog(postgres.asUser(ctx.auth.claims), {
    organizationId,
    from: Temporal.Instant.from("2026-01-01T00:00:00Z"),
    format: "ocsf",
    product: { name: "Acme CRM", vendor_name: "Acme Inc." },
  });
  return new Response(stream, {
    headers: { "content-type": "application/x-ndjson" },
  });
});
```

`format: "ocsf"` maps each entry to an
[OCSF](https://schema.ocsf.io/1.9.0) event (`SPEC_PINS.ocsf`). Row changes
are Entity Management (`class_uid` 3004) with the table and record as the
`entity`; `audit_event()` entries are API Activity (6003) with the event type
as `api.operation`. The activity comes from the event type's last segment:
`created` is Create, `exported` is Read, `renamed` is Update and `revoked` is
Delete; anything else is Other (99) with the event type as `activity_name`.
`toOcsf(entry, product)` maps one entry.

## Retention

`purgeAuditLog` deletes entries past their retention and returns how many.
Without `retention` it calls `purge_audit_log`, which honours an
`audit_retention` SQL hook; with it, each tenant is purged with its own
number of days. `setAuditRetention` reads those days from a column:

```ts title="jobs/purge-audit.ts"
import { purgeAuditLog, setAuditRetention } from "better-supabase/blocks/audit";

await purgeAuditLog(postgres.admin, {
  olderThan: "1 year",
  retention: setAuditRetention(postgres.admin, {
    table: "public.organizations",
    column: "audit_retention_days",
  }),
});
```

A tenant whose column is `null` keeps the `olderThan` default. Run the job
until it returns 0; each call deletes at most `batch` entries per tenant.
