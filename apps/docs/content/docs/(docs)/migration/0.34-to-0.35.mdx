---
title: From 0.34 to 0.35
description: What to check when upgrading to better-supabase 0.35, where blocks run over more of an app's own tables and time tracking locks only logged time.
---

0.35.0 has no codemod and no renamed APIs. Blocks run over more of an app's
own tables, and a few blocks change what they allow. Run
`better-supabase upgrade` and generate a migration, then check the behaviour
changes below. The session, cache and block changes that came after 0.35.0
are in [From 0.35 to 0.37](/docs/migration/0.35-to-0.37).

## Behaviour changes

| Block         | Before                                                           | After                                                                                                                                 |
| ------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Time tracking | a submitted or approved week refuses every change to its entries | it refuses changes to logged time only (start, end or duration, subject, owner and rate); `options.lockedColumns` lists other columns |
| Drive         | a node under a held folder can be trashed, deleted or pruned     | it counts as held                                                                                                                     |
| Drive         | a new top-level node gets an owner grant for its creator         | with `roleFunctions.node`, it gets none; your role function decides                                                                   |

Code that relied on a locked week refusing a change to the billable flag, the
note or one of your own columns has to list those columns in
`options.lockedColumns`.

## New in 0.35

- `upgrade`, `sync` and doctor render adopted tables with the authorization
  provider, so calendar `accessFunctions` in the `{ rows, key }` form and
  drive `roleFunctions` in the `{ rows, roles }` form no longer fail with
  "needs an authorization provider with functions.rowsWith".
- Invoices: `options.chargeExtraColumns` adds your columns to charges, set
  through `charge(id, { fields })`. `options.lineRates: "percent"` keeps line
  discount and tax rates as percentages in your line table (invoices, quotes
  and deals).
- Catalog: `save_product` writes the product's own `price`, `currency` and
  `trackInventory` without a prices table. `options.variantExtraColumns` and
  `options.categoryExtraColumns` let `saveVariant` and `saveCategory` write
  your columns from `fields`.
- Leave: `columns.types.key` and `columns.requests.partial` can map to `null`.
