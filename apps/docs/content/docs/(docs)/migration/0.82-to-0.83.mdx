---
title: From 0.82 to 0.83
description: What to change when upgrading from better-supabase 0.82 to 0.83. The tasks module at version 7, claimNext picks only your own tasks by default, category stages, hold kinds, task reservations and before_task_close on every close.
---

0.83 closes five gaps in the task coordination that shipped in 0.82. It is a
minor release, and below 1.0 a minor version may carry breaking changes. Run
`better-supabase upgrade` to move the `tasks` module to version 7. Each change
is also in the
[changelog](https://github.com/ScaleDockHQ/better-supabase/blob/main/packages/better-supabase/CHANGELOG.md).

| Section                                                | Needs code                                         |
| ------------------------------------------------------ | -------------------------------------------------- |
| [claimNext picks assigned tasks](#claimnext)           | Set `claims.next: "any"` to keep the old pick      |
| [Category stages](#category-stages)                    | None; new option form                              |
| [Hold kinds](#hold-kinds)                              | None; new options                                  |
| [Reserve a task for a profile](#reserve-a-task)        | Read `delegateProfile` if you stored the old label |
| [before_task_close on every close](#before-task-close) | Check a hook that relied on running only in close  |

## claimNext

`claimNext` took the oldest ready task, assigned ones first, and fell back to
unassigned tasks. It now takes only tasks assigned to the caller unless the
config sets `claims.next: "any"`. A session with an `act` claim of kind `agent`
always picks assigned tasks, whatever the option says, and the filters
`assigneeId` of someone else are refused with `TASK_FILTER_FORBIDDEN`. Claiming
a task that is not assigned to an agent is `TASK_NOT_ASSIGNED`. The pick is
ordered by `number`.

## Category stages

`hold.stage`, `claims.startStage` and `claims.expiredStage` take a stage key or
`{ category }`. A category resolves to the first stage of that category in the
task's pipeline. Doctor reports BS245 when the live pipeline has no stage for a
configured key or category.

## Hold kinds

`hold.kinds` lists the kinds `hold` accepts, and anything else is
`TASK_HOLD_INVALID`. `hold.approval.kinds` limits which kinds open an approval
request and must be a subset of `hold.kinds`. Releasing a hold, moving the task
out of the hold stage and closing it now cancel the pending approval request.
`releaseHold` then reports `approvalCancelled` in the `task.hold_released` event.

## Reserve a task

`delegate({ taskId, toUserId, toProfile })` reserves the task for a named
profile of that user. Only that profile of that user can claim it, or a person
with write access, who takes it over. Anyone else gets `TASK_RESERVED`.
`claimNext` takes `filter.delegateProfile`. The task reads back
`delegateProfile: { name, userId }`. A re-delegate, an unassign and a close clear
the reservation, and `task.delegated` carries `toProfile`. Before 0.83 the column
stored the delegating label, which the client never read; the upgrade step clears
those values.

## before_task_close

The `before_task_close(task uuid, outcome text, note text)` hook now runs once
on every path that closes a task, from an after-update trigger, and a hook that
raises refuses the close with its own error. Templates are skipped. It no longer
runs when `reopen` sets the outcome `open`, and it is not called for a task
inserted already closed.
