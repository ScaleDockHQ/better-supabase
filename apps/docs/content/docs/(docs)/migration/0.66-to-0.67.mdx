---
title: From 0.66 to 0.67
description: What to change when upgrading from better-supabase 0.66 to 0.67. Sessions and sign-in run on @supabase/ssr, the lite browser client is removed, every peer range starts at the release the tests run on, the previous majors of SvelteKit, Nuxt, React Router, NestJS, Stripe, expo-server, undici, redis and PowerSync are no longer supported, and better-supabase/eve follows eve 1.0.
---

0.67 calls Supabase only through its own clients: session cookies are read
with the `@supabase/ssr` helpers and written by its `createServerClient`, the
Next.js sign-in flows call auth-js, and the browser client always comes from
`createBrowserClient` (ADR 0846 and ADR 0847). Every peer range now starts at
the release the conformance tests run on and covers one major release
(ADR 0848). It is a minor release, and
below 1.0 a minor version may carry breaking changes. Each change is also in
the
[changelog](https://github.com/ScaleDockHQ/better-supabase/blob/main/packages/better-supabase/CHANGELOG.md).

| Section                                       | Needs code                                                 |
| --------------------------------------------- | ---------------------------------------------------------- |

| [New optional peers](#new-optional-peers)     | None; install one only for the subpath you use             |

## Supabase peers

Install the newest Supabase packages:

```bash
pnpm add @supabase/supabase-js@^2.119.0 @supabase/ssr @supabase/server@^1.9.2
pnpm add -D @supabase/postgrest-typegen@0.8.1
```

`@supabase/config` needs `^1.6.1`. `@supabase/postgrest-typegen` and
`@supabase/mcp-server-supabase` have a floor and no upper bound. The CLI is
tested against postgrest-typegen 0.8.1, so install that release to keep
`database.types.ts` equal to `supabase gen types`.

0.8 marks a `returns table` column and a table argument that can never be
null as not nullable, so a few generated types get narrower; run
`better-supabase gen` after the upgrade. `oxfmt` still starts at 0.66.0, the
version typegen 0.8.1 requires.

## Dropped majors

These majors were in range on 0.66 and are not on 0.67. Upgrade the framework
or SDK first, following its own guide, then better-supabase. After the bump,
`better-supabase doctor` reports every installed peer outside its new range
as BS601.

| Package             | 0.66 accepted | 0.67 accepts   |
| ------------------- | ------------- | -------------- |
| `@sveltejs/kit`     | 2 and 3       | `>=3.2.0 <4`   |
| `nuxt`              | 3 and 4       | `>=4.6.4 <5`   |
| `react-router`      | 7.9 and 8     | `>=8.5.1 <9`   |
| `@nestjs/common`    | 11 and 12     | `>=12.5.0 <13` |
| `stripe`            | 17 to 23      | `>=23.1.0 <24` |
| `expo-server`       | 55 to 58      | `>=58.1.0 <59` |
| `undici`            | 7.30.1 and 8  | `>=8.12.4 <9`  |
| `redis`             | 5 and 6       | `>=6.3.1 <7`   |
| `@powersync/common` | 1 and 2       | `>=2.5.0 <3`   |

`better-supabase/h3/v1` stays: Nuxt 4 still runs on Nitro 2 and H3 1, so `h3`
accepts `>=1.15.11 <3`.

## Expo

`expo-server` 58.1 is Expo SDK 58, which turns on data loaders, middleware and
server rendering with `web.output: "server"` alone. Remove the three
`unstable_` options from the `expo-router` plugin in `app.json`; they are
deprecated in SDK 58 and have no effect. `bsb.loader()` now names
`web.output` when a route renders without a request.

## New optional peers

0.67 declares eight more optional peers for the Vercel integrations:
`@vercel/schedules`, `botid`, `@vercel/firewall`, `@vercel/passport`,
`@vercel/sdk`, `@vercel/functions`, `@vercel/kms` and `@vercel/blob`.
better-supabase types them structurally or loads them on first use, so
nothing changes until you import the subpath that needs one.
[Peers](/docs/getting-started/peers) lists the ranges and subpaths.

## Lite browser client

`better-supabase/client/lite` is removed, along with its optional peers
`@supabase/auth-js` and `@supabase/realtime-js`:

| Before                                                                  | After                                                   |
| ----------------------------------------------------------------------- | ------------------------------------------------------- |
| `import { createLiteBrowserClient } from "better-supabase/client/lite"` | `import { createClient } from "better-supabase/client"` |

A route that used the lite client loads about 12 KB more. Uninstall
`@supabase/auth-js` and `@supabase/realtime-js` if nothing else in the app
imports them.

## Session cookies

`readSession` is replaced by `ssrSession`, which decodes the cookies with the
`@supabase/ssr` helpers and returns a promise. `applyCookieWrites` is no
longer exported: let a `createServerClient` write the cookies.

| Before                       | After                             |
| ---------------------------- | --------------------------------- |
| `readSession(cookies, name)` | `await ssrSession(cookies, name)` |

Chunks that don't parse together now read as no session, as they do in
`@supabase/ssr`.

## Sign-in flows

The Next.js flows (`signInWithPassword`, `verifyOtp`, `signInWithOAuth`,
`exchangeCodeForSession`, the email flows, `verifyMfa` and `signOut`) call
auth-js on a `createServerClient`. Their results don't change, but a few
names do:

| Before                                        | After                                              |
| --------------------------------------------- | -------------------------------------------------- |
| `passwordGrant` from `better-supabase/server` | `signInWithPassword` on a `createServerClient`     |
| error code `code_verifier_missing`            | `pkce_code_verifier_not_found` (auth-js)           |
| verifier cookie `httpOnly`, 10 minutes        | the auth-js verifier cookie `@supabase/ssr` writes |
| `SignInWithOAuthParams.provider: string`      | `Provider` from `@supabase/supabase-js`            |

A magic link or OAuth redirect from a flow that started before the deploy
fails the exchange once with `pkce_code_verifier_not_found`. Show the sign-in
page again so the user can request a new one. Flows the browser client starts
can now finish in `exchangeCodeForSession` on the server.

## Notification avatars

The notifications block's `avatars` option takes a function of the object
path. For a public bucket, pass `getPublicUrl` from a supabase-js client:

```ts
const users = supabase.storage.from("users");

avatars: (path) => users.getPublicUrl(path).data.publicUrl;
```

## Session status

`sessionStatus` now calls `auth.getUser`. A 403 whose body is not Auth's JSON
(a proxy or firewall page) reads as `unknown` instead of `ended`, so it no
longer signs the user out.

## eve 1.0

`better-supabase/eve` follows eve 1.0 and accepts `eve` `>=1.0.0-rc.0 <2`
(ADR 1022). Upgrade eve first with eve's own
[upgrade guide](https://eve.dev/docs/guides/upgrade), then change these:

| Before                                                                  | After                                                                |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `persistSessions` handlers `message.received`, `message.completed`      | `delivery.consumed`, `content.completed`                             |
| `persistSessions` handlers `turn.completed`, `turn.failed`, `cancelled` | `turn.settled`, with the outcome as the run's status                 |
| `EveTokenAuthorization.credentialOwner`                                 | `principalType`, which `credentialAuth` and `openApiAuth` now return |
| `EveApprovalResponseContext` `request.requestId`                        | `request.interactionId`                                              |
| an approval answer `decision: "cancel"`                                 | `decision: "deny"`; `approvalPolicy` treats it as before             |
| `EveApprovalStatus`                                                     | also `{ type: "not-applicable" }` and `{ type: "user-approval" }`    |
| `EveMemoryTool.inputSchema: unknown`                                    | a JSON Schema object, as eve's `MemoryToolSet` requires              |

`defineHook({ events: persistSessions(...) })` needs no change of its own, but
any hook of yours that reads v26 event names stops firing; eve's guide maps
them. Messages that `persistSessions` stores from now on have ids
`<turnId>:<deliveryId>` and `<turnId>:<partId>`, so a turn that started
before the upgrade and finishes after it can store its reply twice.

`eve build` in 1.0 rejects a tool input schema it can't turn into JSON
Schema, such as a plain Valibot schema: wrap it in `toStandardJsonSchema` from
`@valibot/to-json-schema` when you pass it to `supabaseTool`. `queueScheduleProvider` and `queueDynamicSchedules` are new:
they store eve's dynamic schedules in the queue block's drain scheduler (see
[eve on Supabase](/docs/eve#dynamic-schedules)).
