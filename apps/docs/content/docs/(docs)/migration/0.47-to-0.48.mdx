title: From 0.47 to 0.48
description: What to check when upgrading from better-supabase 0.47 to 0.48. The deprecated aliases and options that were due go away, every port needs apiVersion 1, and messaging reads prune record conversations before the per-row check.

0.48.0 removes the deprecated aliases and options that were due, requires
`apiVersion: 1` on every port, and makes messaging reads prune record
conversations. The named presets only gain blocks, so an app that installed one
before can add the new blocks with `better-supabase add`.

| Section                             | Needs code                        |
| ----------------------------------- | --------------------------------- |
| [Removed aliases](#removed-aliases) | Replace every removed name        |
| [Port versions](#port-versions)     | Add `apiVersion: 1` to every port |
| [Messaging reads](#messaging-reads) | Run `better-supabase upgrade`     |
| [Maintenance](#maintenance)         | Apply the bundled migration       |

## Removed aliases

| Removed or changed                                                       | Use instead                                                           |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| `createOAuthServer` and the `OAuth*` type aliases                        | `createOauthServer` and the `Oauth*` types from `blocks/oauth-server` |
| `createRateLimit`, `rateLimited` and `RateLimit*` from `blocks/queue`    | the same names from `better-supabase/rate-limit`                      |
| `receiveEInvoices` options `xmlParser` and `FromUblOptions`              | pass `readUbl: (xml) => fromUbl(xml, options)`                        |
| outbox `legacyEventTypes` and the `currenttype` extension                | the event type `<prefix>.<entity>.<verb>`                             |
| `DbError.legacyHint`                                                     | `DbError.hint`                                                        |
| `SequenceEnrollmentEventData`                                            | `EnrollmentEventData` from `blocks/enrollments`                       |
| `workItemChecklistBinding`                                               | `taskChecklistBinding`                                                |
| `AssistantRunResult.toUIMessageStream`, `totalUsage`, `providerMetadata` | `stream`, `usage` and `finalStep`                                     |
| `sha256Hex` in `sql/shared`                                              | `sha256HexSql`                                                        |

`dbErrorOfStatus` is new: it maps an HTTP status to a `DbError`.

## Port versions

Every port an app plugs in now needs `apiVersion: 1`. The prescription gateway,
the clinical decision support engine and the funding claim format and channel
used to accept a missing `apiVersion`; add `apiVersion: 1` to yours. All ports
now share one check, `portOf`, so the error for a wrong version reads the same
everywhere.

## Messaging reads

A commented subject type whose `permissions.read` names the provider's `rows`
now renders `subject_id in (select s.<id>::text from <subject table> s)` in the
follows branch instead of letting every row reach `can_subject`. The set is a
superset of the rows `can_subject` can pass, because `can_subject` already
requires the record row to be visible under the same policy, so visibility does
not change. It runs once per statement as a hashed subplan, so a conversation in
another tenant no longer calls the provider's row function once per row. A
commented type without `rows` keeps `true`.

`can_subject` and `can` carry `cost 1000`, so the planner keeps the set check
ahead of them. Run `better-supabase upgrade` to rewrite the messaging module's
policies and functions.

## Maintenance

The `maintenance` block calls `better_supabase.rrule_occurrences` and drops
`maintenance_rule_starts`. The migration
`20261102110000_maintenance_use_core_rrule.sql` applies this.
