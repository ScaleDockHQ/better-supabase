---

Blocks cover the tables every app needs. The tables only your app has, such
as `projects` and `tasks`, are plain SQL that you own (ADR 0102). You write
them in `supabase/schemas/<schema>/tables`, one file per table, and
`better-supabase gen` types them like the fixture's own tables. A feature
that needs more than the table, such as realtime or a subject, is a tag in
the table comment.

```sql title="supabase/schemas/public/tables/projects.sql"
create table public.projects (
  id uuid primary key default gen_random_uuid(),
  organization_id uuid not null references public.organizations (id) on delete cascade,
  name text not null,
  budget_minor bigint not null default 0,
  currency text not null default 'EUR',
  deleted_at timestamptz,
  internal_notes text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

alter table public.projects enable row level security;

comment on table public.projects is
  '@bsb subject type=project id-type=uuid tenant=organization_id title=name url=/projects/{id} deleted-at=deleted_at search versions=name,budget_minor,currency; server internal_notes';
```

Run `better-supabase db diff` to write the migration, then `gen`. The policies, grants and indexes are yours too: write them in the same
file, or let a block's policy helpers do it.

## Tags

A tag is `name key=value ...` after `@bsb`, with `;` between tags and `"` to
quote a value that holds spaces. A table has one tag per name, and a config
key of the same meaning wins over the tag. `better-supabase table <name>
enable <feature>` writes a tag for you (see [table](/docs/cli/table)).

| Tag             | What it does                                                                                             |
| --------------- | -------------------------------------------------------------------------------------------------------- |
| `subject`       | Registers the table as a subject type: comments, tags, search, versions and the other blocks reach it.   |
| `realtime`      | Adds the table to the realtime publication and registry.                                                 |
| `audit`         | Writes a row to the audit log for each change.                                                           |
| `audit-reads`   | Audits reads of the table's sensitive columns.                                                           |
| `vector-search` | Keeps an embedding column and its index.                                                                 |
| `json`          | Types the table's jsonb columns, `json meta=Type`.                                                       |
| `expose`        | Exposes the table through the Data API.                                                                  |
| `encrypted`     | Names the columns stored with field encryption, `encrypted diagnosis=text birth_date=date`.              |
| `server`        | Names the columns signed-in users can't select, so `gen` types them as not selectable.                   |
| `events`        | Writes `<type>.created`, `.updated` and `.deleted` to the outbox, `events include="status, project_id"`. |

### The subject tag

`subject type=<name>` takes these arguments, all optional except the type.

| Argument                                                      | Meaning                                                                                                         |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `id`, `id-type`                                               | The id column and its type (`uuid` by default).                                                                 |
| `tenant`                                                      | The tenant column, or `false` for a table with none.                                                            |
| `title`, `url`                                                | The title column and the URL template, `/projects/{id}`.                                                        |
| `scope`, `cascade`                                            | A provider scope whose ids are this subject's ids, and whether deleting the row deletes the module rows for it. |
| `deleted-at`                                                  | The soft delete column.                                                                                         |
| `search`, `search-title`, `search-body`, `search-description` | Index the row for search, or name the columns for each part. `search-exclude` skips some.                       |
| `rank`, `rank-group`                                          | The rank column for manual ordering, and the column it orders within.                                           |
| `versions`, `versions-auto=false`                             | The columns a version keeps (a comma list), and whether saves snapshot on their own.                            |
| `can-<action>`                                                | The permission an action needs, `can-read=projects.read`.                                                       |

A subject that needs a search source other than its own columns, a watch list
or a row grant keeps its entry in `subjects` in the config instead. Subjects
the blocks register for their own tables stay there as well.

## Hidden columns

`server` lists the columns that signed-in users can't select. Revoke the
column grant in SQL, and name the column in the tag so the generated types
leave it out of the readable shape.

## Encrypted columns

`encrypted` names the columns the [field encryption](/docs/blocks/field-encryption)
block seals, each with its decrypted type. Add `audit-reads` to the tag
list to audit reads of those columns.

## Events

`events` writes `<type>.created`, `<type>.updated` and `<type>.deleted` to the
[outbox](/docs/blocks/outbox) from a trigger, named after the subject type.
`events include="status, project_id"` keeps only those columns in the event
data. Rules and workflows consume the events through sinks.

## History

`subject ... versions=name,budget_minor` keeps those columns in each
[version](/docs/blocks/versions) of a row. `versions-auto=false` turns off the
automatic snapshots.

## Rollups and lookups

A rollup (an open task count) or a lookup (a task's project name) is a view
with `security_invoker = true`. Write it in `supabase/schemas/public/views`
and `gen` types it as a read-only table:

```sql title="supabase/schemas/public/views/projects_view.sql"
create view public.projects_view with (security_invoker = true) as
select
  p.*,
  count(t.id) filter (where t.status <> 'done') as open_tasks
from public.projects p
left join public.tasks t on t.project_id = p.id
group by p.id;
```

The caller's row level security applies to the view's source tables. Keep a
view's grants and comment in its own file.

## Enriching a table you already have

Because the tables are your SQL, there is nothing to enrich: write the
columns, policies and grants you want, and the blocks that run over your
tables (see [Your own schemas](/docs/blocks/own-schemas)) use them.

## Moving an existing config

`better-supabase migrate schema-first` turns `tables` entries in the config
into the table files, the comment tags, the views and an
`_custom/app_tables.sql` file for the rest. The command prints a diff first
(see [migrate](/docs/cli/migrate)). Review the files, run `db diff`, and
remove the `tables` key.

The bulk action `appTables.set` goes with the key. Update the selected rows
through the typed repository instead: each row runs as the caller, so the
policies and column grants decide what changes.

```ts
const results = await Promise.all(
  ids.map((id) => db.tasks.update(id, { dueOn })),
);
```

## Create

[Create](https://app.bettersupabase.com/create) keeps its own design format,
which still lists tables with their columns. `init --preset` and
`apply --preset` with a design URL write it into the config (see
[init](/docs/cli/init#a-design-from-create)), and `migrate schema-first`
turns that into table files.
