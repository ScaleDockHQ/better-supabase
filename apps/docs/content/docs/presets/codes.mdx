---
title: Codes and the resolver
description: How better-supabase/preset encodes a preset as a short code, resolves its blocks and writes the config and wiring Create shows.
---

`better-supabase/preset` is the model behind `preset` in the config and
behind [Create](https://bettersupabase.com/create). It runs on every
runtime, including the browser: the resolver reads a generated catalog of
the blocks and never imports the SQL renderers.

```ts
import {
  decodePreset,
  encodePreset,
  namedPreset,
  presetConfigSource,
  resolvePreset,
} from "better-supabase/preset";

const preset = { ...namedPreset("saas"), api: "api", blocks: ["comments"] };
const code = encodePreset(preset); // "1..."
const { preset: decoded, derived } = decodePreset(code);
const resolved = resolvePreset(decoded);
// resolved.blocks: comments, plus tenant, access and updated-at, each with a reason
console.log(presetConfigSource(resolved));
```

## Conventions

Every field has a default, so a preset sets only what differs.

| Field          | Values                                                                                         | Default        | What it sets                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `framework`    | `next`, `vite`, `tanstack-start`, `expo`, `sveltekit`, `nuxt`, `hono`, `astro`, `react-router` | `next`         | the glue Create shows                                                                                                        |
| `platforms`    | `web`, `native`, `both`                                                                        | `web`          | the glue Create shows; `native` needs `expo`                                                                                 |
| `casing`       | `snake`, `camel`                                                                               | `snake`        | `casing`                                                                                                                     |
| `idType`       | `uuid`, `text`, `bigint`, `integer`                                                            | `uuid`         | `blocks.access.idType`                                                                                                       |
| `scope`        | `tenant`, `user`, `none`                                                                       | `tenant`       | `sql.scope`; under `user` or `none`, blocks that need tenants can't install, and the rest need neither `tenant` nor `access` |
| `tenantName`   | `organization`, `workspace`, `team`                                                            | `organization` | `sql.naming.tenant`; a block whose tables or columns the name would take over can't install                                  |
| `access`       | `roles`, `catalog`, `provider`, `custom`                                                       | `roles`        | `blocks.access.model`                                                                                                        |
| `api`          | `none`, `api`                                                                                  | `none`         | `sql.api`                                                                                                                    |
| `integrations` | `next`, `hono`, `orpc`, `edge`, `expo`, `mcp`, `client`, `react` (any number)                  | none           | `integrations`                                                                                                               |

## Codes

A code is a version character followed by base62 of one BigInt. The low
bits hold each field's value index in a fixed number of bits, in the order
of `PRESET_FIELDS`; above them sits one bit per entry of `PRESET_BLOCKS`.
Both lists are append-only. A new block takes the next bit, and a removed
block keeps its bit as a `null` tombstone, so every code keeps decoding.

A new field raises `PRESET_VERSION`. `decodePreset` reads a code from an
older version with the newer fields at their defaults and lists them in
`derived`. A code from a newer release throws and names the upgrade. Each
released version has a frozen fixture of codes in the package tests that
must decode to the same selection forever.

`presetOf` takes a named preset, a code or a `/create?preset=` URL, which
is what the `preset` config key accepts.

## Designs

A preset code holds blocks and conventions. What you add on the Create
canvas, the [app tables](/docs/blocks/app-tables), extra columns on block
tables and where each table sits, goes in a second code that rides on the
URL as `&design=`:

```ts
import {
  designConfigSource,
  designInstallCommand,
  designOf,
  encodeDesign,
  namedPreset,
  resolvePreset,
} from "better-supabase/preset";

const resolved = resolvePreset(namedPreset("crm"));

const code = await encodeDesign({
  appTables: { projects: { columns: { name: { type: "text" } } } },
  extraColumns: { organizations: { tier: "text" } },
  positions: { "public.projects": [120, 40] },
});

console.log(designConfigSource(resolved, (await designOf(code))!, code));
console.log(designInstallCommand(resolved, code));
// npx better-supabase init --preset "https://bettersupabase.com/create?preset=...&design=0..."
```

A design code starts with `0`, the format version, which no preset name or
code starts with, followed by base64url of the design's JSON compressed
with `deflate-raw`. It uses `CompressionStream`, so encoding and decoding
are async and run on every runtime.

The `0` stays the encoding. The JSON's own format goes in a `version` key,
which `encodeDesign` writes only for a design that needs it:
`designFormat(design)` returns `1` when a table or column uses a key added
after the first release (`format`, `options`, `min`, `max`, `comment`,
`identity`, or a table's `id`, `unique`, `indexes` or `comment`), `2` when
a table has a `subject`, `3` when a table has `rollups` or `lookups`, and
`0` otherwise, so older codes stay byte for byte the same. `DESIGN_FORMAT` is
the newest format this release reads; a code with a higher `version` fails
with a message to update better-supabase instead of losing keys.

`decodeDesign` and `designOf` reject what isn't a design: an unknown key, a
table that `appTables` wouldn't accept, a column type outside a plain SQL
type, a block with no table for extra columns, or a code that inflates past
256 KB. `encodeDesign` throws a `TypeError` for an invalid design, and a
`DesignTooLongError` (a `TypeError` with the code's `length`) when a valid
design would pass `MAX_DESIGN_CODE_LENGTH` (6000 characters); download the
config then. Check for `DesignTooLongError` to tell the two apart.

Two helpers check a design before it is encoded. `appReservedColumns(tenant)`
lists the columns every app table can get from its scope (`id`,
`created_at`, `updated_at`, `user_id` and `<tenant>_id`), which a design's
columns may not name. `isAppDefault(type, value)` says whether a column of
`type` accepts `value` as its default.

`diffDesigns(before, after)` lists what changes between two designs, and
`diffAppTables(before, after, { keepMissing })` does the same for two
`appTables` objects; with `keepMissing: true`, a table missing from `after`
is kept instead of dropped, as `apply` merges a design. Each `DesignChange`
has a `kind`, the `table` and `column`, a one-sentence `summary`, and
`breaking`. A dropped or renamed table or column, a type change and a column
made required without a default are breaking, and their `steps` give the
expand-and-contract migration that makes them safe. A change to a table's
rollups or lookups is the safe `table.computed`, because their view keeps
no rows:

```ts
import { diffAppTables } from "better-supabase/preset";

const changes = diffAppTables(
  { notes: { columns: { body: { type: "jsonb" } } } },
  { notes: { columns: { body: { type: "text" } } } },
);
// [{ kind: "column.type", table: "notes", column: "body", breaking: true,
//    summary: "Changes notes.body from jsonb to text.", steps: [...] }]
```

The AI instructions for a design are at
`/create/prompt.md?preset=<code>&design=<code>`.

| Function               | What it does                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------- |
| `designConfig`         | the preset's config with the design merged in; throws for extra columns on a block it doesn't install |
| `designConfigSource`   | `better-supabase.config.ts` with the design, and the `/create` URL with both codes in its comment     |
| `designInstallCommand` | `init --preset` with the quoted URL; the preset command when the code is empty                        |
| `designApplyCommand`   | `apply --preset` with the quoted URL                                                                  |

## Resolving

`resolvePreset(preset)` returns:

| Key            | What it holds                                                                                                         |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| `blocks`       | every block to install, in install order, with `selected`, `requiredBy` and a `reason` such as "required by comments" |
| `integrations` | the soft integrations active between blocks in the set (`comments` works with `notifications`)                        |
| `conflicts`    | what can't install and why: a block that needs tenants under scope `user`, or Expo on `web` only                      |
| `manifests`    | the block manifests that cover the set, for `lib/blocks.ts`                                                           |

What a block requires can depend on the access model: under `provider` and
`custom`, `access` no longer requires `tenant`. `presetBlockConflict` says
why one block can't install before it is selected, which is how Create
disables a block.

`defineConfig` throws when a preset has conflicts, listing each one.

## Generated files

| Function               | Writes                                                                                        |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| `presetConfigSource`   | `better-supabase.config.ts` with every block, each added block marked with its reason         |
| `presetBlocksSource`   | `lib/blocks.ts`: the blocks with a TypeScript client, wired with `defineBlocks`               |
| `presetInstallCommand` | `npx better-supabase init --preset <code>`, which starts a project from the preset            |
| `presetApplyCommand`   | `npx better-supabase apply --preset <code>`, which applies it to an existing project          |
| `presetGlue`           | the registry glue items for the preset's framework and platforms; `glueCommand` installs them |

`scripts/build-catalog.ts` writes the catalog (`src/preset/catalog.generated.ts`)
from the SQL module registry and the block manifests, and
`pnpm catalog:check` fails when it is stale.
