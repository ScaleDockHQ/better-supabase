Deals move through a pipeline of stages. The board orders cards with rank
keys and groups them by stage, the state machine refuses a jump the pipeline
does not allow, and the people watching a deal hear about comments, tags and
stage moves.

## Table

```sql title="supabase/schemas/deals.sql"
create table public.deals (
  id uuid primary key default gen_random_uuid(),
  organization_id uuid not null,
  name text not null,
  stage text not null default 'lead',
  rank text collate "C" not null default 'V'
);
create index on public.deals (organization_id, stage, rank);
alter table public.deals enable row level security;
```

Add read and update policies for the organization's members, as for any
tenant table.

## Config

The `crm` preset brings the SaaS blocks (organizations, notifications, the
outbox, ...) plus parties, pipelines, engagements, tags, comments, custom
fields, saved views and search. The board adds `rank`, `reminders` and a
state machine on top:

```ts title="better-supabase.config.ts"
import { defineConfig } from "better-supabase/config";

export default defineConfig({
  preset: "crm",
  subjects: {
    deal: {
      table: "public.deals",
      idType: "uuid",
      title: "name",
      url: "/deals/{id}",
      rank: { column: "rank", group: "stage" },
    },
  },
  blocks: {
    rank: {},
    reminders: {},
    "state-machine": {
      options: {
        machines: {
          deal: {
            table: "public.deals",
            column: "stage",
            initial: "lead",
            tenant: "organization_id",
            transitions: {
              lead: ["qualified", "lost"],
              qualified: ["won", "lost"],
              won: [],
              lost: ["lead"],
            },
          },
        },
      },
    },
  },
});
```

## Event flow

Each call takes the record as a subject, `deal` being `{ type: "deal", id: dealId }`, and acts in the tenant of the block client (see [one block per request](/docs/blocks/create-blocks#one-block-per-request)).

| The user                         | Call                                                   | Event             | Watchers get        |
| -------------------------------- | ------------------------------------------------------ | ----------------- | ------------------- |
| Comments on a deal               | `comments.create(deal, { body })`                      | `comment.created` | `subject.commented` |
| Tags it                          | `tags.tag(deal, tagId)`                                | `subject.tagged`  | `subject.tagged`    |
| Drags its card to another stage  | `rank.move("deal", dealId, { previous, next, group })` | `status.changed`  | `subject.moved`     |
| Sets a custom field (deal value) | `customFields.setValue(...)`                           | `field_value.set` | map it if you want  |
| Gets a follow-up reminder        | `reminders.deliver(payload)`                           | `reminder.sent`   | `reminder.due`      |

A drag from `lead` onto `won` fails with `STATE_TRANSITION_INVALID`: the
rank and the stage change in one update, and the state-machine trigger
checks it. Move the card back in the UI when `move` returns that error.
