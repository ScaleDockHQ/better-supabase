title: The Create core
description: How better-supabase/create holds the design model, previews and Supabase deploy client that /create and other apps share.
---

`better-supabase/create` is the headless code behind
[Create](https://app.bettersupabase.com/create). It runs on every runtime,
including the browser, and has no dependency beyond the Supabase packages.
Designs stay in the URL or in your own storage, as ADR 0040 requires.

```ts
import { previewFiles, diffDesigns } from "better-supabase/create";
import { namedPreset } from "better-supabase/preset";

const base = { preset: namedPreset("saas") };
const files = previewFiles(base);
console.log(files.map((file) => file.path));
```

`diffDesigns(base, next)` classifies each change as safe or breaking, so an
app can block a breaking change before it deploys.

## Check a design

`checkDesign(input, preset)` runs every rule the canvas and `sql sync` apply
to a design, so a server route, an MCP tool and the canvas give the same
answer. `input` is a design object, a design code or a `/create` URL with
`&design=`; `preset` is a preset name, code or object.

```ts
import { checkDesign } from "better-supabase/create";

const check = await checkDesign(body.design, body.preset);

if (check.ok) {
  // check.code is null when the design is too long for a URL
  save(check.design, check.code);
} else {
  console.log(check.issues);
  // [{ table: "profiles", message: "A block already creates a profiles table. Rename this one." }]
}
```

It never throws for a bad design or preset. Each problem is an issue with the
`table` it is on, or `design` or `preset` for one outside a table: a design
that doesn't parse, a preset that can't install, extra columns on a block the
preset doesn't install, a table name a block already uses, or a reference to a
block table the preset doesn't install. On success, `design` has its empty
parts dropped and `code` is its `encodeDesign` code, or `null` when it would
pass the URL limit; offer the [design file](/docs/presets/codes#design-files)
then.

To check only the shape of an untrusted payload, without a preset, use
`parseDesign` from `better-supabase/preset`.

## Supabase deploy

`better-supabase/create/supabase` signs a user in with Supabase OAuth and
PKCE, seals the session in a cookie value, and wraps the Management API.

```ts
import { managementClient } from "better-supabase/create/supabase";

const client = managementClient(accessToken, fetch);
const projects = await client.projects();
```

Pass your own `fetch` to trace or stub the calls in tests.

## Migrate between versions

`migrationBetween(code, base, next)` writes the migration that takes a project
deployed from one design to the next. It covers added tables and added
columns, which the app-table SQL applies idempotently.

```ts
import { migrationBetween } from "better-supabase/create";

const plan = migrationBetween(code, deployed, edited);

if (plan.ok) {
  await client.applyMigration(ref, "better_supabase_design", plan.sql);
} else {
  console.log(
    plan.reason,
    plan.changes.map((change) => change.steps),
  );
}
```

A `breaking` refusal lists the expand and contract steps for each change. An
`unsupported` refusal covers any other change, such as a new default or a
change outside `appTables`, so a deploy never guesses.

## Validate in Postgres

`better-supabase/create/lite` applies the generated files to an in-memory
PGlite database through the optional `@supabase/lite` peer, and reports what
Postgres rejects before anything reaches a project.

```ts
import { previewFiles } from "better-supabase/create";
import { validateDesign } from "better-supabase/create/lite";
import { encodePreset, namedPreset } from "better-supabase/preset";

const files = previewFiles(encodePreset(namedPreset("saas")));
const { ok, issues, skipped } = await validateDesign(files);
```

PGlite starts without a Supabase project's roles and `auth` schema, so the
function creates a minimal copy first. A module that needs an extension PGlite
doesn't ship (`pgmq` for jobs, `btree_gist` for time tracking) lands in
`skipped` instead of failing. pgTAP is not available through
`@supabase/lite`, so database tests still run with `supabase test db`.

On [/create](https://app.bettersupabase.com/create), the Migrations tab of Get code
has a Validate in Postgres button that runs the same check on the server for
the current selection and design.
