title: App tables and designs
description: Declare the tables your app owns in appTables, add columns to block tables, and carry both in a /create design code.
---

`appTables` declares the tables your app owns next to the blocks.
`better-supabase sql sync` writes them to
`supabase/schemas/900_better_supabase_app_tables.sql` with row level
security that follows `sql.scope`, so you get the same tenant or user
checks the blocks use without writing policies.

```ts title="better-supabase.config.ts"
import { defineConfig } from "better-supabase/config";

export default defineConfig({
  preset: "saas",
  appTables: {
    projects: {
      columns: {
        name: { type: "text", nullable: false },
        budget_minor: { type: "bigint", nullable: false, default: "0" },
        currency: { type: "text", nullable: false, default: "'EUR'" },
        owner_id: {
          type: "uuid",
          references: { table: "auth.users", onDelete: "set null" },
        },
      },
    },
    tasks: {
      columns: {
        project_id: {
          type: "uuid",
          nullable: false,
          references: { table: "projects", onDelete: "cascade" },
        },
        title: { type: "text", nullable: false },
        done: { type: "boolean", nullable: false, default: "false" },
      },
    },
  },
});
```

## Tables

Every app table gets `id` (a `uuid` primary key), the scope column and,
unless `timestamps: false`, `created_at` and `updated_at`. `columns` can't
name these, nor `user_id` or the tenant column (`organization_id`, or
`<sql.naming.tenant>_id`), so changing a table's scope never collides with
one of its columns.

| Key          | Values                    | Default   | What it does                                                                                                                             |
| ------------ | ------------------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `columns`    | column name to column     | none      | the table's own columns, in lower snake case                                                                                             |
| `scope`      | `inherit`, `user`, `none` | `inherit` | `inherit` follows `sql.scope`; `user` keeps rows per user in any scope; `none` lets signed-in users read and only the service role write |
| `timestamps` | `true`, `false`           | `true`    | `created_at` and `updated_at`                                                                                                            |

## Columns

| Key          | Values                                                                                                             | Default  |
| ------------ | ------------------------------------------------------------------------------------------------------------------ | -------- |
| `type`       | `text`, `uuid`, `integer`, `bigint`, `numeric`, `boolean`, `timestamptz`, `date`, `jsonb`, `text[]`                | required |
| `nullable`   | `true`, `false`                                                                                                    | `true`   |
| `default`    | `now()`, `gen_random_uuid()`, `auth.uid()`, `true`, `false`, a number, a `'quoted'` text literal, `'{}'` or `'[]'` | none     |
| `unique`     | `true`, `false`                                                                                                    | `false`  |
| `references` | `{ table }`, `{ block, table }`                                                                                    | none     |

Store money as a `bigint` of minor units next to a `text` currency column,
as the blocks do, instead of `numeric`.

`references` points at another app table, at `auth.users`, or at a block's
logical table (`{ block: "crm", table: "contacts" }`), which follows the
block's renames. `onDelete` takes `cascade`, `restrict`, `set null` or
`no action` (the default). A required column can't use `set null`.

## Extra columns on block tables

`organizations` and `profiles` take `options.extraColumns`, a map of column
name to SQL type, for the fields your app adds to a tenant or a user. See
[SQL](/docs/blocks/sql) for the blocks that accept them.

## Designs

The canvas on [Create](https://bettersupabase.com/create) edits app tables,
extra columns and table positions on top of a preset. It keeps them in a
second code, `&design=`, next to the preset code, so a link reopens the same
canvas. Pass the whole URL to [init](/docs/cli/init#a-design-from-create) or
[apply](/docs/cli/presets#apply) to write the design into the config.

`better-supabase/preset` reads and writes design codes. It runs in the
browser and on every server runtime, and decoding needs no network call.

```ts
import {
  decodeDesign,
  designConfigSource,
  encodeDesign,
  resolvePreset,
  namedPreset,
} from "better-supabase/preset";

const design = {
  appTables: {
    projects: { columns: { name: { type: "text", nullable: false } } },
  },
};

const code = await encodeDesign(design); // "0..."
const decoded = await decodeDesign(code);
console.log(
  designConfigSource(resolvePreset(namedPreset("saas")), decoded, code),
);
```

| Export                                       | What it does                                                                       |
| -------------------------------------------- | ---------------------------------------------------------------------------------- |
| `encodeDesign(design)`                       | the design as a code: `0`, then deflate-raw compressed JSON in base64url           |
| `decodeDesign(code)`                         | the design in a code; throws a TypeError for a code that is malformed or too large |
| `isDesignCode(value)`                        | whether `value` has the shape of a design code                                     |
| `designOf(input)`                            | the design in a `/create` URL or a bare code, or `undefined` when there is none    |
| `designConfig(resolved, design)`             | the config keys the preset and design set                                          |
| `designConfigSource(resolved, design, code)` | `better-supabase.config.ts` for the preset and design                              |
| `designInstallCommand(resolved, code)`       | the `init` command with the quoted `/create` URL                                   |
| `designApplyCommand(resolved, code)`         | the `apply` command with the quoted `/create` URL                                  |

A design code is at most 6000 characters (`MAX_DESIGN_CODE_LENGTH`), so the
URL stays under common length limits. When a design is larger, Create
offers its config to download instead of a link. Positions stay in the code
and never reach the config.
