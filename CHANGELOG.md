# Changelog

## 0.13.0 (2026-10-21)

- Structured, non-throwing design APIs, a provider-neutral OAuth subpath, deploy records and a doctor rule for dropped library functions. See [From 0.11 to 0.12](https://bettersupabase.com/docs/migration/0.11-to-0.12).

  - `parseDesign`, `decodeDesign`, `designFileSource` and `readDesignFile` in `better-supabase/preset` throw a `DesignParseError` with a stable `code` and a JSON Pointer `path`. `safeParseDesign` and `safeDesignFileSource` return `{ ok: false, issues }` instead of throwing. `DesignTooLongError` is a `DesignParseError` with the code `too_long`.
  - `DesignIssue` from `checkDesign` gains `code` and `path`, and a successful `DesignCheck` gains `fitsUrl`.
  - `designSchema` is `parseDesign` as a Standard Schema, and `schemas/design-v1.json` publishes the design as JSON Schema.
  - `DEFAULT_PRESET_NAME`, `defaultPreset()` and `defaultPresetCode()` name the preset Create and `init` start from.
  - `better-supabase/create/oauth` holds PKCE, sealed cookies and an `OAuthSession` shape for any OAuth provider. `seal` and `unseal` take an optional HKDF `info`. `better-supabase/create/supabase` re-exports them, and `SupabaseSession` and `isSession` stay as aliases.
  - `newDeployId()`, `deployQuery(files, { id })` and `DeployRecord` in `better-supabase/create` let a host app match a project to the preset it deployed. `DeployResponse` gains `id`, `preset` and `design`.
  - Doctor's BS235 warns when an unapplied migration drops a `better_supabase` function without creating it again with the same number of arguments, as a schema diff did for `audit()` in 0.11.
- `codemod 0.9` now pins `defaultFormat: "standard"` on an adopted
  `webhooks-out` block that maps no `columns.endpoints.format` and sets no
  `defaultFormat`, which keeps the 0.8 body, and lists `sql add` calls in
  scripts and workflows for review (`add` also wires clients). A new
  `codemod 0.11` pins `defaultFormat: "cloudevents"` under the same conditions,
  since adopt mode requires the key from 0.11. Both list the edit for review.
- Add `better-supabase db diff`, which turns the declarative schema into a migration with the Supabase CLI's command for the workflow and, when the shadow database can't start because no System V shared memory segment is left, diffs inside the running stack instead. `--in-stack` skips the shadow database, `-f <name>` writes the migration, and `$BSB_PG_BIN` names the directory with `pg_dump` and `psql` when the CLI can't find them next to the postmaster.
- Add doctor checks for the machine's System V shared memory, which every local stack and shadow database needs.

  - BS700 warns when 80% of the segment limit is in use (32 on macOS) and names the stacks that hold segments, so `supabase db diff` failing with `could not create shared memory segment` points at `stack prune`.
  - BS701 warns when a stack holds more than its one interlock segment, which means its Postgres sets `shared_memory_type` or `dynamic_shared_memory_type` to `sysv`.
- `doctor`, `gen`, `db query` and `seed --apply` no longer guess port 54322 for the local stack. When `supabase/config.toml` sets no `[db] port` and `supabase status` fails, they stop with `not_found` and name both sources, so a per-worktree stack (`supabase start --runtime native`) can't reach another project's database on 54322. `--stack <name>` (or `$BSB_STACK`) reads `supabase status --stack <name>` when `supabase/stacks/<name>/config.toml` sets no port.
- A `permission` on an action, route, loader or oRPC middleware can now be checked against the row it acts on. Pass `resource: (input, ctx) => AuthorizationResource` next to `permission`: it runs after the session and `requireTenant` checks, gets the validated input and the request's context (`db`, `session`, `tenant`), and its return value replaces the default `{ type: "action" }` or `{ type: "route" }` resource. A loader that throws refuses the caller: a `DbException` keeps its error (such as `not_found`), and any other throw refuses with `forbidden` and `code: "RESOURCE_UNAVAILABLE"`. Every adapter supports it, and `bs.middleware()` in `better-supabase/orpc` now passes the procedure's input to the checks. The loader's context type is exported as `ResourceLoaderContext`.
- Add `better-supabase stack ls` and `stack prune` for the Supabase CLI's managed stacks.

  - `stack ls` lists every stack with its branch, project root and running state, marks stacks whose worktree or branch is gone, and counts the System V shared memory segments each one holds against the system limit.
  - `stack prune` destroys the stacks whose worktree or branch is gone, never the one for this checkout. `--stop-idle` also stops the running stacks of other branches, and `--dry-run` prints the plan. Destroying a stack needs consent in agent mode.
  - The command manifest has a new effect kind, `stacks`, with `read` or `write` access, in `schemas/cli-commands-v1.json`.
- Crop, show and download stored images through Storage image transformations. See [Image transformations](https://bettersupabase.com/docs/platform/storage#image-transformations).

  - `defineBucket` takes `variants`, named transforms such as `thumb: { width: 160, height: 160, resize: "cover" }`. `renderUrl`, `signedUrl` and `publicUrl` accept a variant name wherever they took a transform, and the names are typed. `defineBucket` refuses a side outside 1 to 2500 or a quality outside 20 to 100.
  - `avatarBucket()` and `organizationLogoBucket()` come with `sm`, `md` and `lg` variants: center-cropped squares of 48, 96 and 256 for avatars, and squares of 64, 128 and 256 that fit the whole logo. Pass `variants` to replace them.
  - `useImage(bucket, target, variant)` in `better-supabase/react` returns `src`, a `srcSet` at 1x and 2x, `width` and `height`. Public buckets build the URLs while rendering; private buckets sign them and sign again before they expire.
  - `storageImageSrcSet({ url })` in `better-supabase/storage` builds a `srcset` for a public Storage URL.
  - New types: `ImageTransform`, `ImageVariant`, `ImageSource`, `StorageImage` and `UseImageOptions`.
  - Fix: the `better-supabase/next/image` loader and `storageImageUrl` keep a crop's shape. When `src` carries a `width` and `height`, the height scales with each requested width, so a square crop stays square. A size over 2500 now shrinks both sides by the same factor instead of clamping the width alone.
- Add `authorization.functions.teamIdsOf`, a template that returns the team ids
  a user belongs to. Under the `provider` access model, `team_ids_of()` in the
  `teams` block returns its set instead of reading `team_members`, and
  `saved-views` and `collections` share with those teams even without the
  `teams` block. Doctor BS417 warns when the provider declares a `team` scope,
  one of those blocks is installed, and the template is unset.
- Seed each tenant with the same demo rows. `defineTenantSeed(betterSupabase, (tenant) => fixtures)` in `better-supabase/testing` builds typed fixtures from a tenant id, and `better-supabase seed --tenant <slug>` (or `--tenant '*'`) inserts them for organizations from the organizations block, all in one transaction. The file comes from the new `seed.perTenant` config key (`supabase/seed.tenant.ts` by default). `seedTenantOnCreate(betterSupabase, seed, { sql })` applies the seed to each organization created in development; it runs after the create call and never changes its result.
- Add `codecs: { timestamptz: "utc" }`. `timestamptz` columns stay `string`,
  but every value is rewritten in UTC as ISO 8601 with a `Z` and keeps all its
  fraction digits (`2026-10-21 07:10:00.123456+02` reads as
  `2026-10-21T05:10:00.123456Z`). `infinity` passes through. The default stays
  `"string"`.
- The Vercel Marketplace block serves the Partner API. `marketplace.partnerApi({ resources, plans })` returns one handler for the installation, resource, secret rotation and plan routes. It verifies Vercel's OIDC token (signature against `/.well-known/jwks`, issuer, audience and expiry) and requires its `installation_id` to match the path, answering 401 or 403 as Problem Details. The installation's access token is sealed in Vault, so `accessToken` is now optional. Tenants are tracked per installation and resource, and an empty tenant the integration created is removed with it. A rotation revokes the previous secrets only after the new ones are issued.

  `reportUsage` now sends one request per billing period, with the period total as `periodValue` and the part not reported before as `dayValue`, and no longer sends `planValue`. It moves the reported amount only after Vercel answers 2xx. `marketplace.usageRoute({ secret, usage })` runs it from a cron caller. The SSO exchange reads keys from `https://marketplace.vercel.com/.well-known/jwks`, the path Vercel's discovery document names. Run `better-supabase gen` to apply the module's version 2 upgrade.
- Add `withClaims(postgres, claims, fn)` to `better-supabase/testing`. It runs
  raw SQL as the user the claims describe (`role` and `request.jwt.claims` are
  set, so `auth.uid()`, `auth.jwt()` and RLS apply) inside one transaction that
  always rolls back.
- Two SQL fixes. See [From 0.11 to 0.12](https://bettersupabase.com/docs/migration/0.11-to-0.12) for what to check.

  - `better_supabase.acting_member()` is granted to `service_role` only; `anon` and `authenticated` get `permission denied` instead of an RPC that returned null. `better_supabase.set_actor()` is `security definer`, so the trigger still records the actor for every writer. Run `sql sync` to get the new grant in a migration. If your own SQL calls `acting_member()`, run it as `service_role` or from a `security definer` function.
  - Module file headers no longer carry the package version, so a release doesn't rewrite every module file. The `@bs-module` marker keeps the module version, and a header written by an older release still counts as current. `ModuleLayout.version` is deprecated.
- The Record grid recipe, on the UI recipes page and in the skill reference, now notes that a copy of `@reui/data-grid` installed from ReUI 2.8.0 or earlier doesn't repaint after an edit that keeps the row count. Reinstall it with `npx shadcn add @reui/data-grid --overwrite`, or add `table.options.data` to the dependency list of the `value` memo in `DataGridProvider`.
- Security fix for support session upload claims. In 0.12.0, `claimSignedUpload`, `claimReserved` and the blocks' `confirm` and `commit` claimed any object without an owner on a path the target may insert into. That could include a file the service role stored earlier, such as an export or an import, which the claim then handed to the target and stamped with the session. A claim now only takes an object without an owner whose `updated_at` is at or after the session's `startedAt`, and in a versioned bucket only the current version. Older objects are refused with `403` `AccessDenied`. An upsert reservation that replaces such an object during the session can still be claimed.

  Required change for direct callers: `SupportStorageOptions.session` now needs `startedAt`. The server already passes the whole `SupportSession`; pass it too when you call `supportStorage` yourself. `uploadToSignedUrl` on the server removes what it stored when the claim fails or is refused. A refused claim after a browser upload, including `upload` with `onProgress`, removes nothing, because the claim can't tell that upload from another object without an owner; `sweep` removes what is never claimed. A claim of an object the target already owns now succeeds even when it is older than the session. The impersonation page documents the limits of the claim's insert rehearsal and how to sweep uploads that are never claimed.

## 0.12.0 (2026-10-20)

- Check a Create design in one call, and hand designs too large for a URL to `init` as a file.

  - `checkDesign(input, preset)` in `better-supabase/create` checks a design object, design code or
    `/create` URL against a preset with every rule the canvas and `sql sync` apply. It returns
    `{ ok: true, design, code }`, where `code` is `null` for a design too long for a URL, or
    `{ ok: false, issues }`, and never throws for a bad design.
  - `parseDesign(value)` in `better-supabase/preset` checks the shape of a design object.
  - `designFileSource` and `readDesignFile` write and read a design file
    (`better-supabase.design.json`, `DESIGN_FILE`), which holds the preset code and the design as
    JSON with no length limit.
  - `init --preset ./better-supabase.design.json` and `apply --preset ./better-supabase.design.json`
    read a design file like a Create URL. `DesignTooLongError` now points to it.
- Doctor's BS503 warns when the shell exports a `SUPABASE_*` variable (plain or with a browser prefix) that differs from the running local stack, so an app started from that shell would talk to another project. It reads `supabase status` only when such a variable is exported, and shows redacted values.
- `better-supabase env` writes the full stack env: `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` under their plain names for server code, the same two with the browser prefix, and the new `SUPABASE_JWKS_URL`. The secret key, database URL and JWT secret never get a browser prefix. `--write <file>` names the file (`--out` still works), and `--prefix` takes a framework name (`next`, `vite`, `expo`, `nuxt`, `astro`, `sveltekit`), `none`, or the prefix itself. Help lists a long alias after the flag it stands for.
- Add `better-supabase run -- <cmd>`. It starts the command with the running stack's URL and keys set, over the shell's exported variables and every `.env` file, passes its output and exit code through, and forwards Ctrl+C and `SIGTERM`. When an exported `SUPABASE_*` variable differs from the stack, `run` warns and names it, showing the host and port of a URL or a `sha256:` fingerprint of a key, never the value.
- Server auth can run hermetic. `auth.jwks: false` (or `null`) verifies against no keys and never fetches one, ignoring `SUPABASE_JWKS` and `SUPABASE_JWKS_URL`; `null` used to fall through to the JWKS URL. `createServer({ env })` also takes the variables as an object (`{ SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY }`) and loads only those, never filling a missing one from `process.env`. `createTestSigner().jwks` is typed so it passes to `auth.jwks` without a cast.
- Signed uploads work in a writable support session. `supportStorage` used to refuse `createSignedUploadUrl` and `uploadToSignedUrl` with `SUPPORT_STORAGE_WRITES`, so `bucket.connect(storage).reserve(...)` and the blocks' browser uploads failed, and an admin could not upload a file as the user. Now `createSignedUploadUrl` runs the same dry run as `upload` as the target (an insert, or an upsert with `upsert: true`, refused with Storage's `403`), then the service client signs the URL.

  An object uploaded to a signed URL has no owner, so a claim step finishes the upload. It checks again that the target may insert at the path, then makes the target the owner and adds `supportSessionId` and `supportAdminId` to the object's `user_metadata`. It claims only an object without an owner; one another user owns is refused with `403` `AccessDenied`. The `StorageApi` that `supportStorage` returns has `claimSignedUpload(bucket, path)`, and a connected bucket has `claimReserved(reservation)`, which succeeds without a request outside a support session, so call it after a reserved upload and before you record the file. `uploadToSignedUrl` on the server and `upload` with `onProgress` claim on their own.

  The blocks claim in their own finish step: `attachments.confirm`, `drive.commit` and the AI files block's `files.confirm` claim the upload before they record it. A refused claim keeps the record pending and returns the block's `forbidden` (`ATTACHMENT_FORBIDDEN`, `DRIVE_FORBIDDEN`, `AI_FILE_FORBIDDEN`) or `not_found` (`ATTACHMENT_NOT_UPLOADED`, `AI_FILE_NOT_UPLOADED`) error. Outside a support session they make no extra request. Read-only sessions still refuse every write with `SUPPORT_READ_ONLY`.
- Create moved to the cloud app. `createUrl()` and the comment `init` writes above a preset now link to `https://app.bettersupabase.com/create`. Old `bettersupabase.com/create` links redirect there with their query string, and `presetOf` and `designOf` still read both.

## 0.11.0 (2026-10-20)

- `bs.admin()` returns an `AdminDb` with `$authAdmin`, the typed Auth admin API (`auth.admin`) of the secret-key client, so cron jobs and webhook handlers can create, invite, ban and delete users without a second client. Request repositories don't have it. The `AdminDb` type is exported from `better-supabase/server`.
- Fixes and additions from adopter feedback.

  New API:

  - `matchDbError(error, matchers)` maps a `DbError` kind to a value, for `orThrow` factories.
  - `paginate({ withCount: true })` returns `total` on offset and cursor pages and narrows its type to `number`. On a cursor page after the first, it sends one extra request to count the matching rows.
  - `db.$buckets.<name>` is each bucket registered with `betterSupabase.buckets()`, connected to `db.$storage`. The type follows `$with()`, `$withoutPlugins()` and the `db`, `sql` and `admin()` repositories of `createServer(betterSupabase)`, and `db.$storage` on a server `Db` now uses the caller's Storage client. Every framework adapter (`next`, `hono`, `orpc`, `edge`, `mcp`, `astro`, `sveltekit`, `react-router`, `solid-start`, `tanstack-start` and `expo`) carries the registry through a new trailing `B` type parameter, so `ctx.db.$buckets.<name>` is typed in handlers, actions and routes. `ctx.db.$storage` and `ctx.db.$buckets` now work on request contexts.
  - `better-supabase/testing` adds `scopedSeed`, `withRollback` and `TestUser.context`. `asUser` also turns off supabase-js trace propagation.
  - `gen` emits `WritableColumnOf` and `GeneratedColumnOf`, and the schema types export `WritableColumns` and `GeneratedColumns`.

  Fixes:

  - `update` with no columns to write reads the row and returns it, and `updateMany` returns a count of 0, instead of failing with `invalid_request`. A caller that relied on that error needs to check for empty data itself. A plugin that leaves the patch empty still gets `invalid_request`.
  - `createMany`, `upsertMany`, `updateMany` and `deleteMany` type their result by `returning`. `orderBy` accepts `undefined` values and `updateMany` data no longer infers readonly arrays.
  - The client follows auth state only when the supabase client has it.
  - Text filter escaping and case rules are documented, and `$rpc` typing is pinned as stable API.

  The generated column `memberships.tier_role` in `supabase/` is a repo-only test fixture and does not ship in the package.
- Attachments and comments subjects taken from the subject registry now carry the registry's per-action keys: `subjects.<type>.permissions.upload` and `manage` for attachments, `create` and `moderate` for comments. The registry's `read` stays the key for reading the subject itself. `blocks.<block>.options.subjects.<type>.permissions` overrides them key by key.

  Doctor `BS345` warns when an attachments subject has no `read` or `upload` key of its own while its table's policies check more than tenant membership, so any member of the tenant would get the files of rows they can't open.
- Adds `better-supabase db query <file...>`, which runs SQL files as multi-statement scripts against the local stack or the database in the connection string. `--single-transaction` keeps all files or none.
- `seed --apply` and `db query` accept `--stack <name>` (or `$BSB_STACK`) to connect to the stack in `supabase/stacks/<name>/config.toml` instead of the default local stack.
- Closes the gaps found on 0.9.0: `audit()` takes `tenant_path` and `tenant_function`, `admin({}, { as })` names the acting member, optional RPC arguments accept `undefined`, `createHono` and `createNext` share one server, OAuth server resources follow RFC 8707, `jwtType` validates `typ`, billing webhooks cover subscriptions, usage meters count distinct or computed values, and the doctor flags partitions without RLS (BS343).
- `bs.middleware()` from `better-supabase/expo` hands the session it refreshed to the loaders and `bs.request` calls of the same request. They read the new cookies without calling Auth again, so a loader with `refresh: false` renders signed in on the first paint after an expired token, and each request makes at most one Auth call. Loaders that run without middleware still refresh on their own.
- Add the `ieq` filter operator for case-insensitive equality, on text columns and jsonb `path` filters. It sends `ilike` with `%`, `_` and `\` escaped, so `where: { email: { ieq: input } }` matches only that address in any case.

  Add the `require-escape-like` rule to `better-supabase/lint`, on as a warning in `configs.recommended`. It flags a `like` or `ilike` value taken from a variable, a property, or a template or concatenation without `escapeLike(...)`.
- Realtime topic triggers read less and send less.

  - A generated trigger function reads each parent row once per changed row, into a local record, however many values, payload keys and topics use it. A custom payload is built once for all topics. Before, every lookup ran again for the payload, for each topic's values and for each nested level. Run `sql sync` to rewrite the functions; the messages they send don't change.
  - `topic.trigger(table, { when: { changed: ["status"] } })`, and `when` on a `realtime.triggers` entry, send an update only when one of the listed columns changed. On a trigger for updates alone it becomes the trigger's `when` clause, otherwise an early return in the function. Inserts and deletes always send.
  - A delete whose lookup finds no parent row, such as a child removed by `on delete cascade`, raises a warning that starts with `better-supabase: realtime lookup found no row` instead of skipping the topic silently. The Realtime docs have a new "Deletes and cascades" section.
- New block `better-supabase/blocks/vercel-marketplace` (`better-supabase add vercel-marketplace`): installations, resources, plans, invoices and meter reports for an app listed on the Vercel Marketplace. `createVercelMarketplace()` verifies webhooks (`x-vercel-signature`, HMAC-SHA1), applies `integration-configuration.removed` and invoice events (the newest event wins), exchanges SSO codes and verifies the `id_token` against Vercel's JWKS, submits invoices and reports usage with retries. Only the service role calls it.
- `vercelQueueBackend(client)` in `better-supabase/blocks/jobs` runs jobs on Vercel Queues. Pass a `PollingQueueClient` from `@vercel/queue` (new optional peer, `>=0.8 <0.9`). It passes `testQueueBackend`. Vercel Queues keeps no dead letters and has no schedules, so `schedule` still needs the SQL backend.
- An adopted `webhooks-out` endpoints table has to choose its body format.

  Breaking config change: in adopt mode, when `columns.endpoints.format` maps no column, `sql sync` now refuses the config unless `blocks.webhooks-out.options.defaultFormat` is set. Without a format column every endpoint gets `defaultFormat`, whose default changed from the 0.8 body (`standard`) to `cloudevents` in 0.9, so receivers broke without any change to the config. Set `defaultFormat: "standard"` to keep the 0.8 body, `"cloudevents"` if your receivers read CloudEvents, or map a format column.

  Doctor reports the same config as `BS344` (warning), and says whether the table has no `format` column or one the config doesn't map. The webhooks-out page lists `defaultFormat` and the version 3 columns, and the new 0.9 to 0.10 guide covers the change.
- `seal` from `better-supabase/create/supabase` now accepts any object, so other OAuth connections on the Create page can reuse the sealed session cookie.

## 0.10.0 (2026-10-20)

- Adopt mode takes enum columns where a block writes kinds and subject types. In adopt mode the tags block casts the `kind` and `subjectType` values it writes and compares, and `next_number` casts the `entity`, to the adopted column's type through the new `better_supabase.as_column_type(value, target)`, so `kind public.organization_tag_kind` or `entity public.workflow_subject_type` works. An enum on any other text column a block writes a parameter or computed value into is refused instead of failing at runtime (columns a block writes only string literals into, such as the teams `status`, may stay enums): `sql sync` and `better-supabase adopt` report it when the schema files declare the enum, and doctor reports it as BS342. A module table spec lists its castable columns in `typed`, and `ModuleContext.cast(table, column, value)` renders the cast.
- App table columns take `access: "read"` or `access: "server"`. `sql sync` then grants `select`, `insert` and `update` on the columns signed-in users may use, by name, and the `<table>_view` lists only the readable columns. `gen` marks a server column `selectable: false`, so a default select leaves it out and the row type makes it optional; select it by name with the service role client. `appTables` refuses a required restricted column without a default, and a server column used as the subject title, a search column, a rollup or lookup source, or in `events.include`. Tightening a column's access is a breaking change in the design diff, and Create design codes with `access` use format 5.

  `doctor` counts column grants for BS106, so a table whose grants list columns no longer reports "Table not granted to the Data API".
- App tables emit outbox events, and rules and the workflow builder react to them (ADR 0048).

  - `appTables.<name>.events` (`true` or `{ on, include }`) adds a trigger that writes `<type>.created`, `<type>.updated` and `<type>.deleted` to the outbox in the same transaction as the write. The payload is an `AppTableEventData` with the id, the tenant, the subject, the `include` columns and, on update, the changed columns. It needs the outbox block. `gen blocks` writes `appTableEvents`, a typed event map.
  - `createRuleSink` runs the rules for each outbox event and dispatches their actions, and `WorkflowBuilder.sink()` starts the event triggers that match.
  - Rules get the built-in handlers `notifyAction`, `setFieldAction`, `webhookAction` and `workflowAction`.
  - A change to `events` is the safe design change `table.events`, and a design with `events` is format 4.

  `gen` tags `appTableEvents` and `appTableEventSchemas` with `@public`, so Knip doesn't report the one an app leaves unused.
- App tables get record history with per-field restore, upsert imports and a bulk set action.

  - `appTables.<name>.subject.versions` (`true` or `{ columns, auto }`) registers the table with the versions block, so its rows get snapshots without an entry in `subjects`. It needs the versions block, and a design with `versions` is format 4. A change to it is the safe design change `table.versions`.
  - `versions.restoreFields(id, fields)` writes back only the named fields. It fails with `VERSION_FIELDS_EMPTY`, `VERSION_FIELD_UNKNOWN` or `VERSION_RESTORE_UNSUPPORTED`.
  - `appTableImport` builds an import keyed on one of the table's unique sets that updates existing rows (`update: "fill"` or `"overwrite"`), and `previewImport` counts the rows it would create, change and leave unchanged.
  - The bulk action `appTables.set` sets columns on the selected rows through `app_table_set`, as the caller. A row fails with `APP_TABLE_SET_EMPTY`, `APP_TABLE_SET_COLUMN`, `APP_TABLE_SET_SUBJECT` or `APP_TABLE_SET_NOT_FOUND`.
  - New recipes: record history and upsert import.
- Add `better-supabase mcp`, which serves the CLI to a coding agent as an MCP server on stdio. The read-only tools (`doctor`, `blocks_list`, `config`, `gen_check`, `apply_dry_run` and others) run by default, and `--allow-writes` adds `gen`, `sql_sync`, `apply` and `add`, each of which asks for the user's consent with a token before it writes. `better-supabase/mcp` now exports `answerMessage` and `answerLine` for serving a `ProtocolServer` over any transport, and `createMcp` logs one warning naming the tools a missing authorizer hides.
- Add `better-supabase/create` and `better-supabase/create/supabase`. They hold the design model, schema parsing, previews, deploy plans, Supabase OAuth and the Management API client that `/create` used to keep inside the marketing app, so other apps can build on them.
- Add `better-supabase/create/lite`. `validateDesign(files)` applies the files Create generates to an in-memory PGlite database through `@supabase/lite` and reports what Postgres rejects. Modules that need `pgmq` or `btree_gist` are reported as skipped.
- Doctor checks the migrations that haven't run for statements that lock a table with rows: an index built without `concurrently` (BS229), a foreign key or check added without `not valid` (BS230), a column type change or `set not null` without a validated check (BS231), a column added with a volatile default (BS232), a migration that takes an exclusive lock before `set lock_timeout` (BS233), and drops or renames (BS234, info). With `--db-url` it checks the migrations the database hasn't applied; offline, the ones after the new `doctor.migrationSafety.since` setting, or the newest one. `init` and `adopt` set `since` to the newest migration.
